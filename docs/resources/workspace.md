# anthropic_workspace (Resource)

Creates and manages an Anthropic Workspace via the Admin API.

> **API**: `POST/GET/POST/POST /v1/organizations/workspaces[/{id}][/archive]` (Admin API).
> **Auth**: Admin API key (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`): a Claude Console Admin API key, or a personal or service account key not scoped to a workspace, or the provider's `aws` block on Claude Platform on AWS. Not available to Claude Enterprise organizations.
> **Beta header**: None.
> **Cost**: Free.

> **Note on deletion:** Deleting this resource **archives** the workspace rather than permanently deleting it, because the Anthropic API does not expose a delete operation for workspaces. An archived workspace is removed from state and Terraform will recreate it on the next apply.

## Example Usage

```hcl
resource "anthropic_workspace" "example" {
  name = "Example Workspace"

  data_residency = {
    workspace_geo          = "us"
    default_inference_geo  = "global"
    allowed_inference_geos = ["unrestricted"]
  }

  # Keys must not begin with "anthropic". To remove every tag, set `tags = {}`.
  tags = {
    env  = "example"
    team = "platform"
  }

  # Write-once CMEK key (requires CMEK enabled for the organization and an
  # existing key configuration); changing it forces a new workspace.
  # external_key_id = "ekey_..."
}

output "workspace_id" {
  description = "ID of the workspace."
  value       = anthropic_workspace.example.id
}

output "workspace_display_color" {
  description = "Display color assigned to the workspace in the Console."
  value       = anthropic_workspace.example.display_color
}

output "workspace_compartment_id" {
  description = "Encryption compartment ID of the workspace (reference it in the KMS key policy for CMEK on AWS)."
  value       = anthropic_workspace.example.compartment_id
}
```

## Tags

The API merges tags on update (verified against the live API on 2026-10-08): keys sent are upserted, keys not sent are kept, a key sent as `null` is deleted, and an empty object changes nothing. The provider therefore sends the planned keys plus `null` for every key removed from the configuration since the last apply, and omits `tags` when nothing changed. Keys must not begin with `anthropic` (case-insensitive); this is rejected at plan time, and the API rejects it as well. Omitting `tags` leaves them unmanaged (the API's current tags are kept in state); set `tags = {}` to remove all of them.

## Customer-managed encryption key

`external_key_id` attaches a CMEK key configuration (`ekey_...`) at creation, or later to a workspace that has no key yet (an in-place update). The API treats it as **write-once**: an attached key cannot be detached or replaced, so changing or removing an attached key forces a new workspace. Use the read-only `compartment_id` in your KMS key policy when configuring CMEK on AWS.

## Claude Platform on AWS

With the provider's `aws` block, the workspace is managed through the Claude Platform on AWS gateway (verified offline only, see the provider documentation):

- The workspace is bound to the AWS region of the provider alias that creates it, and is reachable through that region's endpoint only.
- `external_key_id` is the ARN of an AWS KMS key rather than an `ekey_...` ID: a single-Region key in the same AWS account and region, whose key policy grants the `aws-external-anthropic.amazonaws.com` service principal access. There is no separate validation: the gateway encrypts and decrypts with the key when it is attached, so a key policy problem fails that create or update. When the key policy is restricted to the workspace's `compartment_id`, the workspace must exist before the policy can name it, so attach the key in a second step ([CMEK on Claude Platform on AWS](https://platform.claude.com/docs/en/manage-claude/cmek-claude-platform-on-aws)).
- `data_residency.workspace_geo` is not configurable on this platform ([data residency](https://platform.claude.com/docs/en/manage-claude/data-residency)); leave it unset. `allowed_inference_geos` and `default_inference_geo` work as on the Claude API.
- Whether `tags` relate to the AWS resource tags of the workspace ARN is not documented; they are sent as on the Claude API.

## Claude Models on Google Cloud

Not available with the provider's `google_cloud` block: on Claude Models on Google Cloud (Anthropic managed), workspaces are created, renamed and archived in the Claude Console only (Settings > Workspaces), and the gateway serves no workspace route. Planning this resource there fails with an error naming the platform.
