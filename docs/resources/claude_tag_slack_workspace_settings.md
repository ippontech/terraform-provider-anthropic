# anthropic_claude_tag_slack_workspace_settings (Resource)

Manages the Claude Tag settings of a Slack workspace, through the [Claude Tag API](https://platform.claude.com/docs/en/manage-claude/claude-tag-api#slack-workspaces): the five settings every channel of the workspace inherits unless it sets its own (`instructions` excepted, which channels add to). Workspaces are connected in claude.ai, not through the API, so the workspace must already be set up. The resource manages the settings only: creating it does not connect the workspace, and destroying it clears the settings without disconnecting the workspace.

> **API**: `GET /v1/organizations/claude_tag/slack_workspaces?slack_workspace_id=...` (find), `GET|POST /v1/organizations/claude_tag/slack_workspaces/{id}` (Claude Tag API).
> **Auth**: Claude Enterprise scoped Admin API key with the `read:claude_tag` and `write:claude_tag` scopes (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`), created by the primary owner in claude.ai under Organization settings > API. A Claude Console Admin API key does not work. The key must belong to the organization as a whole.
> **Beta header**: `experimental-claude-tag-2026-10-21`, sent by the provider (the endpoints answer 404 without it).
> **Availability**: beta, Claude Enterprise organizations with Claude Tag set up and a Slack workspace or Enterprise Grid connected; not Claude Console organizations.
> **Rate limits**: two budgets per organization, shared by all its keys: reads (every `GET`) and changes (every `POST` and `DELETE`). A `429` is retried after its `retry-after`.

## Behavior

- **Create adopts the workspace.** It finds the workspace by Slack's own ID (`slack.workspace_id`) and sends only the settings that differ from what it stores. A workspace that is not set up is an error: an organization owner connects it in claude.ai. A workspace the organization owns only through an Enterprise Grid is set up by Claude's first use in it, or by the first channel set up in it with `anthropic_claude_tag_slack_channel`.
- **The configuration owns the five settings**: one it does not declare is cleared on the workspace, which then inherits it from the organization's Slack defaults. See `anthropic_claude_tag_slack_channel` for the plan-time checks, the environment and runner pool rules and read-only mode, which apply here too.
- **Changing `slack.workspace_id` manages another workspace**: the resource is replaced, which clears the settings of the first workspace and adopts the second.
- **Destroying it clears the settings it stores** (each sent as `null`), so the workspace inherits them all from the Slack defaults again. The workspace stays connected: no endpoint removes one. A runner pool, which the API cannot clear, stays, with a warning.
- A workspace disconnected and connected again has a new `slws_` ID: the refresh drops the old one (after checking the API is reachable, as for channels) and the next apply adopts the new one.

## Example Usage

```hcl
# Settings every channel of a connected workspace inherits unless it sets its
# own; channels add their instructions to these.
resource "anthropic_claude_tag_slack_workspace_settings" "main" {
  slack = {
    workspace_id = "T01ABCD2EFG"
  }

  instructions = "Answer in English unless asked otherwise."
  guest_policy = "restrict"
}

output "workspace_id" {
  description = "Claude Tag ID of the workspace (slws_...)."
  value       = anthropic_claude_tag_slack_workspace_settings.main.id
}
```

## Schema

### Required

- `slack` (Attributes) Slack's own ID of the workspace (the API's `slack` object). The workspace must be set up in Claude Tag already. Changing it manages another workspace. (see [below for nested schema](#nestedatt--slack))

### Optional

- `enabled` (Boolean) Whether Claude is on in the workspace (claude.ai: **Enable Claude Tag in Slack**). Omitted, the setting is cleared on the workspace, which then inherits it.
- `environment_id` (String) The cloud environment sessions in the workspace run in: an active environment (`env_...`) of the Claude Enterprise organization. Checked when written, not again. A self-hosted runner pool (`ccpool_...`) set in claude.ai is kept, but cannot be set, changed or cleared through the API. Whether an environment created with `anthropic_environment` in a Claude Console workspace is accepted here is not verified. Declare a runner pool's ID to keep it. Omitted, the setting is cleared on the workspace, which then inherits it.
- `guest_policy` (String) What Claude does in a channel while a Slack guest is in it: `allow` (claude.ai: **Full access**), `restrict` (**Restrict**) or `channel_only` (**Channel only**; refused when not available to the organization). Omitted, the setting is cleared on the workspace, which then inherits it.
- `instructions` (String) Custom instructions Claude reads in every session in the workspace. At most 8,192 characters after leading and trailing white space is trimmed; blank text is refused here (omit the attribute to clear the setting). Instructions are additive: the text of every level that sets them is joined, broadest first. Omitted, the setting is cleared on the workspace, which then inherits it.
- `model` (String) The model new sessions in the workspace start on: a model ID the organization can use with Claude Tag, at most 128 characters. Checked when written, not again. Omitted, the setting is cleared on the workspace, which then inherits it.

### Read-Only

- `created_at` (String) RFC 3339 timestamp of when the workspace was set up.
- `id` (String) The workspace's Claude Tag ID (prefixed `slws_`).
- `updated_at` (String) RFC 3339 timestamp of the last change to Claude Tag's record of the workspace.
