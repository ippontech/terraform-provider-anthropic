# anthropic_plugin_version (Resource)

Uploads a version of an organization-owned plugin through the Claude Enterprise [Plugins API](https://platform.claude.com/docs/en/manage-claude/plugins-api). A version is an immutable snapshot of the plugin's files.

> **API**: `POST /v1/organizations/plugins/{plugin_id}/versions`, `GET /v1/organizations/plugins/{plugin_id}/versions/{version}` (Plugins API).
> **Auth**: Claude Enterprise Admin API key with the `read:plugins` and `write:plugins` scopes (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`), created by the primary owner in claude.ai under Organization settings > API. A Claude Console Admin API key does not work.
> **Beta header**: `ce-plugins-2026-09-01`, sent by the provider (the endpoints answer 404 without it).
> **Availability**: beta, Claude Enterprise organizations only, and not organizations with HIPAA readiness enabled.
> **Cost**: Free.

## Behavior

- **Every input forces a new version**, and so does any edit to the uploaded files: `source_hash` is recomputed from them at every plan. The manifest's `name` must be the plugin's `name`.
- **Git metadata is left out.** `.git` directories and files under `source_dir`, at any depth, are neither uploaded nor hashed, so `source_dir` can be a Git checkout of the plugin: a fresh clone or a fetch does not force a new version.
- **Served or stored.** While the plugin is not pinned, the new version is served to members as soon as it is stored. Once the plugin is pinned (`served_version_id` on `anthropic_plugin`), it is stored but not served until chosen.
- **Content scanning.** With content scanning on, the version's `content_scan` reads `processing` after the upload, and the verdict shows on a later refresh. A served version is withheld from members until its scan is `completed` with `pass` or `warn`: pin the plugin first if members should keep the current version meanwhile.
- **Destroy only removes the version from state**, with a warning: the API cannot delete a single version, so it stays in the plugin's history until the plugin is deleted. Replacing this resource therefore adds a version each time.
- The upload is not idempotent: the provider never resends it after a server error, only when the API asks for it (`registration_pending` with `x-should-retry: true`), which stores one more identical version.

## Example Usage

```hcl
resource "anthropic_plugin" "example" {
  source_dir = "${path.module}/sales-toolkit"
}

# Publishes the directory's content as a version of the plugin, and publishes
# it again whenever a file in it changes: the content hash is recomputed at
# every plan. (Creating the plugin above uploaded its first version, so the
# first apply stores two versions of the same files.)
resource "anthropic_plugin_version" "example" {
  plugin_id     = anthropic_plugin.example.id
  source_dir    = "${path.module}/sales-toolkit"
  release_notes = "Adds the account research skill."
}

output "plugin_version_id" {
  description = "ID of the version."
  value       = anthropic_plugin_version.example.id
}

output "content_scan_status" {
  description = "Status of the version's content scan (processing right after the upload, null when scanning is off)."
  value       = try(anthropic_plugin_version.example.content_scan.status, null)
}
```

## Schema

### Required

- `plugin_id` (String) ID of the organization-owned plugin, in a `manual` marketplace, to add the version to (prefixed `plugin_`).

### Optional

- `release_notes` (String) Release notes, shown in the version history in claude.ai (up to 5,000 characters).
- `source_archive` (String) Local `.zip` or `.plugin` archive holding the plugin.
- `source_dir` (String) Local directory holding the plugin, with its manifest at `.claude-plugin/plugin.json` declaring the plugin's `name`. Every regular file under it is uploaded under its path within the directory, except Git metadata (`.git`, at any depth), which `source_hash` leaves out too; symbolic links are refused. Exactly one of `source_dir` and `source_archive` is required.

### Read-Only

- `components` (Attributes List) The version's components, null when not recorded. (see [below for nested schema](#nestedatt--components))
- `content_scan` (Attributes) The version's content scan, null when it was not scanned. An upload starts `processing`; the verdict arrives later and shows on the next refresh. Members are served a version only once its scan is `completed` with `pass` or `warn`. (see [below for nested schema](#nestedatt--content_scan))
- `created_at` (String) RFC 3339 timestamp of the upload.
- `created_by` (Attributes) Who uploaded the version, null when not recorded. (see [below for nested schema](#nestedatt--created_by))
- `description` (String) The manifest's `description`, or null.
- `display_name` (String) The manifest's `displayName`, or null.
- `id` (String) The version's ID (prefixed `pluginver_`).
- `manifest_version` (String) The manifest's `version`, normalized for display (a leading `v` dropped), or null. Not unique.
- `reach` (String) How far the version reaches: `remote` (declares an MCP server or a CLI), `privileged` (runs or takes effect on members' machines: hooks, settings, pre-approved tools) or `contained`; null when unclassified.
- `source_hash` (String) SHA-256 of the uploaded content, recomputed at every plan so that an edit to the files forces a new version: for an archive, the hash of its bytes (as `filesha256()` gives it); for a directory, a hash over every file's path and content.

## Import

Import is not supported: the API cannot say which local files a version came from.
