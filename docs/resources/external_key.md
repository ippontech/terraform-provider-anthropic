# anthropic_external_key (Resource)

Registers a customer-managed encryption key (CMEK) with the organization via the Admin API: a record that points to a key in AWS KMS, Google Cloud KMS or Azure Key Vault. Creating it is what **Add key** does in the Claude Console. A workspace then uses the key once you set its `external_key_id` (on `anthropic_workspace`) to this resource's `id`.

Before you create it, CMEK must be turned on for the organization and the key must exist in your KMS with access granted to Anthropic: follow the setup guide for [AWS KMS](https://platform.claude.com/docs/en/manage-claude/cmek-aws-kms), [Google Cloud KMS](https://platform.claude.com/docs/en/manage-claude/cmek-google-cloud-kms) or [Azure Key Vault](https://platform.claude.com/docs/en/manage-claude/cmek-azure-key-vault). The [Admin API calls](https://platform.claude.com/docs/en/manage-claude/cmek-admin-api) are documented for Claude Platform; on Claude Enterprise or Claude Platform on AWS, follow your [setup page](https://platform.claude.com/docs/en/manage-claude/cmek#set-it-up).

> **API**: `POST /v1/organizations/external_keys`, `GET/POST/DELETE /v1/organizations/external_keys/{id}` (Admin API).
> **Auth**: Admin API key (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`).
> **Beta header**: None.
> **Cost**: Free.

## Lifecycle

A key is `unattached` until a workspace uses it, then `attached` for good: a workspace cannot detach or replace its key, and archived workspaces still count. The [key lifecycle](https://platform.claude.com/docs/en/manage-claude/cmek-key-lifecycle) page explains what each action does to your data.

- **Unattached**: every attribute can change in place, `provider_config` included (even the provider), and destroying the resource deletes the key record.
- **Attached**: only `display_name` can change. A plan that changes `geo` or `provider_config` fails with an error, because data already encrypted needs the original key; register the new key as another `anthropic_external_key` and use it from a new workspace instead. Destroying the resource fails too, since the API refuses to delete a key that any workspace uses: the plan warns about it, and the apply reports it. To stop managing the key without deleting it, use a `removed` block with `lifecycle { destroy = false }`, or `terraform state rm`.

Deleting the key record never touches the key in your KMS. Deleting or disabling the key in your KMS is what makes the data it protects unreadable.

This resource does not check that Anthropic can reach the key. Use **Verify** in the Claude Console, or `POST /v1/organizations/external_keys/{id}/validate`, before attaching it.

On Claude Platform on AWS, the API identifies a key by its AWS KMS key ARN instead of an `ekey_...` ID, so `id` holds the ARN. The deprecated `role_arn` field is ignored by the API and not exposed.

## Example Usage

```hcl
# A key in AWS KMS. Its key policy must grant Anthropic's role access first
# (see the CMEK setup guide); `region` is derived from the ARN when omitted.
resource "anthropic_external_key" "example" {
  display_name = "prod-us-key"
  geo          = "us"

  provider_config = {
    type    = "aws"
    kms_arn = "arn:aws:kms:us-east-2:111122223333:key/abcd1234-5678-90ab-cdef-000011112222"
  }
}

# A key in Google Cloud KMS, by its full resource name.
resource "anthropic_external_key" "gcp" {
  display_name = "prod-us-key-gcp"

  provider_config = {
    type     = "gcp"
    key_name = "projects/my-project/locations/us-east1/keyRings/anthropic/cryptoKeys/anthropic-cmek"
  }
}

# A key in Azure Key Vault. Omit `client_id` to use Anthropic's multitenant app.
resource "anthropic_external_key" "azure" {
  display_name = "prod-us-key-azure"

  provider_config = {
    type      = "azure"
    vault_uri = "https://my-vault.vault.azure.net"
    key_name  = "anthropic-cmek"
    tenant_id = "00000000-0000-0000-0000-000000000000"
  }
}

# Attaching a key to a workspace cannot be undone: the workspace keeps it for
# good, the key's provider_config freezes and the key can no longer be deleted.
#
# resource "anthropic_workspace" "encrypted" {
#   name            = "Encrypted Workspace"
#   external_key_id = anthropic_external_key.example.id
# }

output "external_key_id" {
  description = "ID of the AWS external key, to set as a workspace's external_key_id."
  value       = anthropic_external_key.example.id
}

output "external_key_attachment" {
  description = "Whether a workspace uses the AWS key (`attached` or `unattached`)."
  value       = anthropic_external_key.example.attachment
}
```

## Schema

### Required

- `provider_config` (Attributes) Where the key lives in your KMS. `type` selects the provider and which of the other attributes apply. Editable while the key is `unattached`, provider included: once a workspace uses the key, any change fails at plan time, because data already encrypted needs the original key to be decrypted. The deprecated `role_arn` is ignored by the API and not exposed. (see [below for nested schema](#nestedatt--provider_config))

### Optional

- `display_name` (String) Human-friendly name (1 to 255 characters). Always editable; removing it clears the name.
- `geo` (String) Data residency geo that selects the regional validator for this key. Only `us` is supported today; the API applies its default when omitted. Editable while the key is `unattached`: changing it on an attached key fails at plan time.

### Read-Only

- `attachment` (String) `attached` when at least one workspace, live or archived, encrypts its data with this key; `unattached` otherwise. Only an `unattached` key can have its `geo` and `provider_config` changed, or be deleted.
- `created_at` (String) RFC 3339 timestamp of when the key was registered.
- `id` (String) Identifier of the external key: a tagged ID prefixed `ekey_`, or the AWS KMS key ARN for organizations on Claude Platform on AWS. This is the value `anthropic_workspace.external_key_id` takes.
- `updated_at` (String) RFC 3339 timestamp of the last update.

### Nested Schema for `provider_config`

Required:

- `type` (String) KMS provider: `aws`, `gcp` or `azure`.

Optional:

- `client_id` (String) `azure` only. Application (client) ID of a single-tenant app registration in your directory. Omit it to use Anthropic's multitenant app.
- `key_name` (String) `gcp`: full resource name of the Cloud KMS key (`projects/.../locations/.../keyRings/.../cryptoKeys/...`). `azure`: name of the key within the vault. Required when `type` is `gcp` or `azure`.
- `kms_arn` (String) `aws` only. Full ARN of the AWS KMS key (at most 2048 characters). On Claude Platform on AWS the key must be a single-Region key in the organization's own AWS account; alias ARNs are rejected. Required when `type` is `aws`.
- `region` (String) `aws` only. AWS region of the key. Derived by the API from `kms_arn` when omitted.
- `tenant_id` (String) `azure` only. Microsoft Entra (Azure AD) tenant ID of the vault. Required when `type` is `azure`.
- `vault_uri` (String) `azure` only. Key Vault data-plane URI: `https://{vault-name}.vault.azure.net` or `https://{hsm-name}.managedhsm.azure.net`. Required when `type` is `azure`.

## Import

Import an external key by its ID (`ekey_...`, or the KMS key ARN on Claude Platform on AWS):

```shell
terraform import anthropic_external_key.example ekey_01SDCCSbTxrXDpWc1phhtcfK
```
