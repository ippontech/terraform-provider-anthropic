# anthropic_memory (Resource)

Creates and manages a memory: a single text document at a hierarchical path inside an `anthropic_memory_store` (beta). Memories are addressed by a stable `mem_...` ID, independent of their `path`, so renaming a memory (changing `path`) preserves its `id` and version history.

> **API**: `POST/GET/POST/DELETE /v1/memory_stores/{memory_store_id}/memories[/{id}]` (Managed Agents API).
> **Auth**: Standard API key (`api_key` / `ANTHROPIC_API_KEY`).
> **Beta header**: `agent-memory-2026-07-22`.

> ⚠️ Optimistic concurrency: every update sends a `content_sha256` precondition built from the last known state. If the memory was modified out-of-band (e.g. by an agent session) since Terraform last read it, the API rejects the update with a `memory_precondition_failed_error` (HTTP 409), and this provider surfaces it as an error rather than overwriting the remote content. Run `terraform plan` or `terraform apply -refresh-only` to pick up the current remote content, then re-apply.

Content is capped at 100 kB (102,400 bytes); this is validated client-side at plan time as well as enforced by the API. Deleting a memory does not erase its version history: prior versions remain retrievable via the API for at least the version retention period.

## Example Usage

```hcl
resource "anthropic_memory_store" "notes" {
  name        = "agent-notes"
  description = "Notes accumulated by the agent across sessions."
}

# A top-level memory
resource "anthropic_memory" "readme" {
  memory_store_id = anthropic_memory_store.notes.id
  path             = "/README.md"
  content          = "# Notes\n\nThis store holds cross-session context for the agent."
}

# A memory nested under a subdirectory-like path
resource "anthropic_memory" "project_notes" {
  memory_store_id = anthropic_memory_store.notes.id
  path             = "/projects/acme/notes.md"
  content          = "Acme project: prefers concise responses, uses Terraform for infra."
}

output "memory_id" {
  description = "ID of the top-level memory."
  value       = anthropic_memory.readme.id
}

output "memory_content_sha256" {
  description = "SHA-256 digest of the memory's content, used as the update precondition."
  value       = anthropic_memory.readme.content_sha256
}
```

## Schema

### Required

- `content` (String) UTF-8 text content of the memory. Maximum 100 kB (102,400 bytes).
- `memory_store_id` (String) ID of the memory store this memory belongs to (a `memstore_...` value).
- `path` (String) Hierarchical path of the memory within the store, e.g. `/projects/foo/notes.md`. Must start with `/`, contain at least one non-empty segment, and be at most 1024 bytes. Must not contain empty, `.` or `..` segments. Case-sensitive and unique within the store. Changing this renames the memory in place; the `id` is preserved.

### Read-Only

- `content_sha256` (String) Lowercase hex SHA-256 digest of the UTF-8 `content` bytes (64 characters). Used as the optimistic-concurrency precondition on update.
- `content_size_bytes` (Number) Size of `content` in bytes (the UTF-8 plaintext length).
- `created_at` (String) Creation timestamp (RFC 3339).
- `id` (String) Unique identifier for the memory assigned by the API (e.g. `mem_...`). Stable across renames.
- `memory_version_id` (String) ID of the `memory_version` representing this memory's current content (a `memver_...` value). Changes on every mutation.
- `type` (String) Object type. Always `memory`.
- `updated_at` (String) Last update timestamp (RFC 3339).

## Import

Import an existing memory using a composite ID in the form `<memory_store_id>:<memory_id>`:

```shell
terraform import anthropic_memory.example <memory_store_id>:<memory_id>
```
