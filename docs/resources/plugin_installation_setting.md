# anthropic_plugin_installation_setting (Resource)

Manages who can use an organization-owned plugin in a Claude Enterprise organization, through the [Plugins API](https://platform.claude.com/docs/en/manage-claude/plugins-api#installation-settings): the installation setting the plugin holds for the whole organization (`target = "organization"`) or for one RBAC group (`target` = the group's `rbac_group_` ID).

> **API**: `POST/DELETE /v1/organizations/plugins/{plugin_id}/installation_settings/{target}`, `GET /v1/organizations/plugins/{plugin_id}/installation_settings` (Plugins API).
> **Auth**: Claude Enterprise Admin API key with the `read:plugins` and `write:plugins` scopes (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`), created by the primary owner in claude.ai under Organization settings > API. A Claude Console Admin API key does not work.
> **Beta header**: `ce-plugins-2026-09-01`, sent by the provider (the endpoints answer 404 without it).
> **Availability**: beta, Claude Enterprise organizations only, and not organizations with HIPAA readiness enabled.
> **Cost**: Free.

## Behavior

- **What members get.** The organization-wide value is the plugin's own `organization` setting, or else its marketplace's default (`anthropic_plugin_marketplace_settings`), or else `not_available`. A member in one or more groups holding a setting gets the most permissive of those groups' values instead (`required`, then `auto_install`, `available`, `not_available`): a group's setting replaces the organization-wide value for its members, it does not add to it.
- **Create is an upsert.** A target that already holds a setting (set in claude.ai, say) is overwritten and adopted. Setting the `organization` target stops the plugin inheriting its marketplace's default, even with the same value.
- **Destroy removes the target's own setting**: for `organization`, the plugin returns to its marketplace's default; for a group, its members fall back to the organization-wide value or to their other groups' settings. Deleting the plugin or the group removes its settings too, which the next refresh shows.
- **Writes for one plugin are sent one at a time.** The API can refuse concurrent setting writes for the same plugin with a 503, so the provider serializes them (within one provider configuration) and resends a write the API marks as safe to retry.
- A member-owned plugin has shares instead of installation settings (404).

## Example Usage

```hcl
# Roll a plugin out to a pilot group: its members get it installed (and can
# remove it), while everyone else can install it on request.
resource "anthropic_plugin_installation_setting" "pilot" {
  plugin_id               = "plugin_01Hq3vX8kZcN2mB7pR4tY9wL"
  target                  = "rbac_group_01F3xQqQzXyWvUtSrQpOnMlK"
  installation_preference = "auto_install"
}

resource "anthropic_plugin_installation_setting" "organization" {
  plugin_id               = "plugin_01Hq3vX8kZcN2mB7pR4tY9wL"
  target                  = "organization"
  installation_preference = "available"
}

output "pilot_setting_id" {
  description = "ID of the pilot group's setting (<plugin_id>:<target>)."
  value       = anthropic_plugin_installation_setting.pilot.id
}
```

## Schema

### Required

- `installation_preference` (String) What the target's members get: `required` (installed, cannot be removed), `auto_install` (installed, can be removed), `available` (installed on request) or `not_available` (hidden).
- `plugin_id` (String) ID of the organization-owned plugin (prefixed `plugin_`).
- `target` (String) Whose setting this is: `organization` for the plugin's organization-wide setting, or an RBAC group's ID (prefixed `rbac_group_`) for that group's own setting.

### Read-Only

- `created_at` (String) RFC 3339 timestamp of when the target was first given a setting for this plugin.
- `id` (String) `<plugin_id>:<target>`: a setting has no ID of its own.
- `target_type` (String) `organization` or `rbac_group`.
- `updated_at` (String) RFC 3339 timestamp of the setting's last change.
