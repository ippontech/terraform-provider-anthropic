# anthropic_spend_limit (Resource)

Sets a spend limit via the Admin API: a cap on metered spend for one scope and period.

- A **Claude Enterprise** organization sets `user` limits: a per-member override of the limit the member would otherwise inherit from their group, seat tier or the organization. Those defaults are configured in claude.ai and cannot be set here.
- A **Claude Console** organization sets `organization` and `workspace` limits, monthly and always with an amount. This is an early access preview: contact your Anthropic account team to request access.

Any other combination is rejected by the API with a 400.

> **API**: `POST /v1/organizations/spend_limits` (upsert), `GET` and `DELETE /v1/organizations/spend_limits/{spend_limit_id}` (Admin API, [reference](https://platform.claude.com/docs/en/api/beta/organization/spend_limits/set)).
> **Auth**: `admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`. For a Claude Enterprise organization, a **scoped Admin API key** created by the primary owner with the `read:spend_limits` and `write:spend_limits` scopes; usage credits must be turned on in claude.ai billing settings.
> **Beta header**: None.
> **Cost**: Free.

> **Note on adoption:** the API upserts on (`scope`, `period`). Creating this resource when a limit already exists for that pair **adopts** it and overwrites its amount, and destroying the resource then deletes it. Two `anthropic_spend_limit` resources with the same scope and period manage the same limit and will fight. When one instance sets a pair during the apply that destroys another instance holding the same limit (a `count` that shrinks, instances re-keyed without `moved` blocks, a `create_before_destroy` replacement), the destroy leaves the limit in place with a warning, since the upsert kept its ID for the instance that set it. `scope` and `period` force replacement; `amount` is updated in place.

> **Note on `amount`:** a non-negative integer decimal string in the minor unit of `currency` (cents for USD): `"50000"` is $500.00. Leaving it out on a `user` limit sets an explicit no-limit override for that period only; caps for other periods still apply. Deleting a `user` limit returns the member to the limit they inherit for that period, or leaves them unlimited if there is none.

## Example Usage

```hcl
# Claude Enterprise: a monthly cap of $500.00 (amounts are in cents for USD)
# on one member, overriding what they would inherit from their seat tier,
# group or the organization.
resource "anthropic_spend_limit" "member" {
  scope = {
    type    = "user"
    user_id = "user_01WCz1FkmYMm4gnmykNKUu3Q"
  }
  period = "monthly"
  amount = "50000"
}

# Claude Enterprise: no daily cap for the same member, whatever they would
# inherit. Omitting amount sets an explicit no-limit override for this period
# only; the monthly cap above still applies.
resource "anthropic_spend_limit" "member_daily_unlimited" {
  scope = {
    type    = "user"
    user_id = "user_01WCz1FkmYMm4gnmykNKUu3Q"
  }
  period = "daily"
}

# Claude Console (early access preview): a monthly cap on one workspace.
#
#   resource "anthropic_spend_limit" "workspace" {
#     scope = {
#       type         = "workspace"
#       workspace_id = "wrkspc_01JwQvzr7rXLA5AGx3HKfFUJ"
#     }
#     amount = "100000"
#   }

output "member_spend_limit_id" {
  description = "ID of the member's monthly spend limit."
  value       = anthropic_spend_limit.member.id
}

output "member_spend_limit_currency" {
  description = "Billing currency the amount is expressed in (minor units)."
  value       = anthropic_spend_limit.member.currency
}
```

## Schema

### Required

- `scope` (Attributes) What the limit applies to. Part of the upsert key with `period`, so changing it forces replacement. Any combination other than `user` (Claude Enterprise) or `organization` / `workspace` (Claude Console) is rejected by the API with a 400. (see [below for nested schema](#nestedatt--scope))

### Optional

- `amount` (String) Limit as a non-negative integer decimal string in the minor unit of `currency` (cents for USD): `"50000"` is $500.00. Omit it (or set `null`) on a `user` limit for an explicit no-limit override for this period; `organization` and `workspace` limits always carry an amount. Changing it updates the limit in place.
- `period` (String) Window the limit resets over: `daily`, `weekly` or `monthly` (default). `organization` and `workspace` limits are monthly only. Part of the upsert key with `scope`, so changing it forces replacement.

### Read-Only

- `created_at` (String) RFC 3339 timestamp of when the limit was created.
- `currency` (String) ISO 4217 code of the organization's billing currency, the unit of `amount`.
- `id` (String) ID of the spend limit (`spl_...`). An amount change shows it as known after apply: if the limit was deleted outside Terraform since the last refresh, the set creates it again under a new ID.
- `is_enabled` (Boolean) Read-only. `false` when extra usage is switched off for the organization (`organization` limit); the amount is kept and applies again once it is switched back on. Always `true` for other limits.
- `updated_at` (String) RFC 3339 timestamp of when the limit was last modified.

## Import

Import an existing `user`, `organization` or `workspace` limit using its ID (limits of other scope types are read-only):
