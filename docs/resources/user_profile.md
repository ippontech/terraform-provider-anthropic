# anthropic_user_profile (Resource)

Creates and manages a user profile (beta): an identity representing an end-user of a platform's product, or a
resold-to company, on whose behalf the platform's API key calls the API.

> **API**: `POST/GET/POST /v1/user_profiles[/{id}]` (beta, no `DELETE`).
> **Auth**: Standard API key (`api_key` / `ANTHROPIC_API_KEY`).
> **Beta header**: `user-profiles-2026-08-18`.

-> This beta is not generally available. As of 2026-09-30 the endpoint returns `404` for organizations that have not been enrolled.

> ⚠️ Verify the feature is enabled for your organization before relying on this resource. The `404` returned when
> it is not is the same response `GET /v1/user_profiles/{id}` gives for a profile that was genuinely deleted
> out-of-band — the two cases are indistinguishable from the response alone. `Read` treats either case as "gone" and drops the resource from
> Terraform state (emitting a warning), so if the beta is disabled or the API key loses access, every managed
> profile silently disappears from state on the next refresh; the next apply then tries to re-create it, which
> either fails (beta still disabled) or, once the beta is enabled again, creates a duplicate — one that this
> resource cannot delete, since there is no delete endpoint. Investigate a "not found" warning before assuming a
> profile was actually deleted.

> ⚠️ No delete endpoint: the Anthropic API does not currently expose a way to delete a user profile. Running
> `terraform destroy` (or removing the resource from configuration) only forgets it in Terraform state — a warning
> is emitted — the profile itself continues to exist at Anthropic.

`metadata` uses merge semantics on update, not the null-based PATCH semantics used elsewhere in this provider
(vaults, memory stores): a key present in config overwrites the stored value, a key omitted from config is left
untouched server-side, and a key removed from config is cleared by sending it with an empty string value. This is
handled transparently; configuring `metadata` declaratively works the same way as any other resource in this
provider.

## Example Usage

```hcl
resource "anthropic_user_profile" "example" {
  access_type = "application"
  external_id = "customer-4821"
  name        = "Acme Corp"

  metadata = {
    tier = "gold"
  }
}

output "user_profile_id" {
  description = "ID of the created user profile."
  value       = anthropic_user_profile.example.id
}

output "user_profile_access_type" {
  description = "Access type of the created user profile."
  value       = anthropic_user_profile.example.access_type
}
```

## Schema

### Required

- `access_type` (String) How the platform uses the API on behalf of the entity this profile represents. `application`: the platform sells a product that uses the API behind the scenes, and the profile represents an individual end-user of that product. `passthrough`: the platform resells raw inference, and the profile identifies the resold-to company.

### Optional

- `external_id` (String) Platform's own identifier for this user. Not enforced unique. 1-255 characters (the API's own maximum is 255; a minimum of 1 is enforced here because an empty string round-trips through the API as null, which would otherwise make `external_id = ""` an inconsistent-apply error).
- `metadata` (Map of String) Arbitrary key-value metadata. Up to 16 pairs; keys 1-64 characters; values 1-512 characters (empty values are rejected by the API — updates use an empty string internally to remove a key, but a value configured here must be non-empty).
- `name` (String) Real-world name of the entity this profile represents (company or individual). For a resold-to company this is that company's name. 1-255 characters (see `external_id` for why the empty string is rejected).

### Read-Only

- `created_at` (String) Creation timestamp (RFC 3339).
- `id` (String) Unique identifier for this user profile assigned by the API (prefixed `uprof_`).
- `trust_grants` (Attributes Map) Trust grants for this profile, keyed by grant name. A key is omitted when no grant is active or in flight for it. (see [below for nested schema](#nestedatt--trust_grants))
- `type` (String) Object type. Always `user_profile`.
- `updated_at` (String) Timestamp of the last update (RFC 3339).
