# anthropic_claude_tag_bundle_target (Resource)

Attaches a Claude Tag [Access bundle](https://claude.com/docs/claude-tag/admins/add-connections#create-a-bundle) to a set-up Slack channel or Slack workspace, through the [Claude Tag API](https://platform.claude.com/docs/en/manage-claude/claude-tag-api#bundle-targets). A Bundle attached to a workspace can be used in the workspace and in every channel in it; one attached to a channel, in that channel only. Bundles themselves are created and edited in claude.ai; the API lists and attaches them.

> **API**: `POST /v1/organizations/claude_tag/bundles/{bundle_id}/targets`, `GET|DELETE /v1/organizations/claude_tag/bundles/{bundle_id}/targets/{target_id}` (Claude Tag API).
> **Auth**: Claude Enterprise scoped Admin API key with the `read:claude_tag` and `write:claude_tag` scopes (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`), created by the primary owner in claude.ai under Organization settings > API. A Claude Console Admin API key does not work. The key must belong to the organization as a whole.
> **Beta header**: `experimental-claude-tag-2026-10-21`, sent by the provider (the endpoints answer 404 without it).
> **Availability**: beta, Claude Enterprise organizations with Claude Tag set up and a Slack workspace or Enterprise Grid connected; not Claude Console organizations.
> **Rate limits**: two budgets per organization, shared by all its keys: reads (every `GET`) and changes (every `POST` and `DELETE`). A `429` is retried after its `retry-after`.

## Behavior

- **The target is the Claude Tag ID** of the channel (`slack_channel_id`, `slch_...`) or of the workspace (`slack_workspace_id`, `slws_...`), exactly one of them, not Slack's own IDs (which the channel and workspace types hold under `slack`). The channel or workspace must already be set up: attaching never sets a channel up, so reference `anthropic_claude_tag_slack_channel.<name>.id` to order the two.
- **Create adopts an attachment made in claude.ai**: attaching a pair that is already attached returns it, with the conditions set in claude.ai unchanged. A new attachment gets the default conditions (set and shown in claude.ai only). The same pair always has the same `btgt_` ID.
- There is no update: changing any argument detaches and attaches again. Destroying it detaches the Bundle; attaching or detaching changes no setting.
- Removing the channel removes its attachments: the next refresh drops the target, and the next apply attaches it again once the channel is set up again.
- The Bundle that an on-call setup attaches, and a channel or workspace an on-call setup manages, cannot be changed through the API (400). Attachments made in claude.ai to the Slack defaults, or by a rule over many channels, are not Bundle targets.

## Example Usage

```hcl
resource "anthropic_claude_tag_slack_channel" "support" {
  slack = {
    workspace_id = "T01ABCD2EFG"
    channel_id   = "C05HJKL6MNP"
  }
  enabled = true
}

# Give the support channel the "Support tools" Access bundle, in the same run
# that sets the channel up, so its first session already has its tools.
resource "anthropic_claude_tag_bundle_target" "support_tools" {
  bundle_id        = "capp_011CZkZjLP1cWxj5EtMmdgbq"
  slack_channel_id = anthropic_claude_tag_slack_channel.support.id
}

# Make the "Monitoring" bundle available in a whole workspace (its slws_ ID,
# for instance anthropic_claude_tag_slack_workspace_settings.main.id).
resource "anthropic_claude_tag_bundle_target" "monitoring" {
  bundle_id          = "capp_011CZkZqWx4mTr8vLp2NbHsK"
  slack_workspace_id = "slws_011CZkZnWa7xPc3uJfZe5LgT"
}

output "support_tools_target_id" {
  description = "ID of the support channel's attachment (btgt_...)."
  value       = anthropic_claude_tag_bundle_target.support_tools.id
}
```

## Schema

### Required

- `bundle_id` (String) ID of the Access bundle (prefixed `capp_`), from `anthropic_claude_tag_bundles`.

### Optional

- `slack_channel_id` (String) Claude Tag ID (prefixed `slch_`) of the channel to attach the Bundle to, such as `anthropic_claude_tag_slack_channel.<name>.id`; not Slack's own channel ID. Exactly one of `slack_channel_id` and `slack_workspace_id`.
- `slack_workspace_id` (String) Claude Tag ID (prefixed `slws_`) of the workspace to attach the Bundle to, such as `anthropic_claude_tag_slack_workspace_settings.<name>.id`; not Slack's own workspace ID.

### Read-Only

- `created_at` (String) RFC 3339 timestamp of when the Bundle was attached.
- `id` (String) The Bundle target's ID (prefixed `btgt_`). The same pair always has the same ID.
- `type` (String) `slack_channel` or `slack_workspace`.

## Import

Import an attachment as `<bundle_id>:<target_id>`, since a target's paths need its Bundle's ID:

```shell
terraform import anthropic_claude_tag_bundle_target.support_tools capp_011CZkZjLP1cWxj5EtMmdgbq:btgt_011CZkZpBv9yQd6wKhAr8MnU1CZkZwPd5fSj8tMxUr3ZcH
```
