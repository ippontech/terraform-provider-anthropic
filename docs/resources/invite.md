# anthropic_invite (Resource)

Creates and manages an invitation for a user to join the organization via the Admin API.

> **API**: `POST/GET/DELETE /v1/organizations/invites[/{id}]` (Admin API, [reference](https://platform.claude.com/docs/en/api/organization/invites/create)).
> **Auth**: Admin API key (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`). With a non-empty `rbac_group_ids`, a Claude Enterprise **scoped Admin API key** created for all linked organizations, carrying `write:rbac_groups` in addition to `write:members`.
> **Beta header**: None.
> **Cost**: Free.

> **Note on updates:** There is no update operation on this endpoint: changing `email`, `role` or `rbac_group_ids` replaces the invite (a new invitation email is sent). Switching `rbac_group_ids` between unset and `[]` changes nothing, since both mean no group. The resource remains managed after acceptance or expiration while the API still returns the invite. Deleting this resource cancels the invite when the API permits it.

> **RBAC groups (Claude Enterprise):** `rbac_group_ids` lists the RBAC groups (`anthropic_rbac_group`) the person is added to when they accept; a `managed` member's permissions come from the custom roles attached to their groups. To assign groups to someone who has not joined yet, use it rather than `anthropic_rbac_group_member`, which needs an existing member. The membership of a group provisioned by your identity provider (`source_type = "scim"`) is managed there, and organizations whose identity provider provisions users (JIT or SCIM) cannot create invites through the API at all ([guide](https://platform.claude.com/docs/en/manage-claude/user-management#create-an-invite)).

> **Expired invites:** Terraform does not automatically re-invite a user after the invite expires. To send a new invitation email, explicitly replace the expired invite with `terraform apply -replace=anthropic_invite.example`.

## Example Usage

```hcl
# Claude Console organization: invite a developer.
resource "anthropic_invite" "example" {
  email = "new-teammate@example.com"
  role  = "developer"
}

output "invite_id" {
  description = "ID of the invite."
  value       = anthropic_invite.example.id
}

output "invite_email" {
  description = "Email address the invite was sent to."
  value       = anthropic_invite.example.email
  sensitive   = true
}

output "invite_status" {
  description = "Status of the invite."
  value       = anthropic_invite.example.status
}

# Claude Enterprise organization: invite a managed member who joins an RBAC
# group on acceptance, and so gets the custom roles attached to the group.
# The scoped Admin API key needs write:rbac_groups in addition to write:members.
resource "anthropic_rbac_group" "engineering" {
  name = "Engineering"
}

resource "anthropic_invite" "engineer" {
  email          = "new-engineer@example.com"
  role           = "managed"
  rbac_group_ids = [anthropic_rbac_group.engineering.id]
}

output "engineer_invite_rbac_group_ids" {
  description = "RBAC groups the invited engineer joins on acceptance."
  value       = anthropic_invite.engineer.rbac_group_ids
}
```

## Schema

### Required

- `email` (String) Email address of the person to invite. Immutable after creation — changing this forces a new resource.
- `role` (String) Organization role to grant once the invite is accepted. The valid set depends on the organization's type: Console organizations use `user`, `developer`, `billing`, `admin`, `claude_code_user`; Enterprise organizations use `user`, `managed`, `owner`, `membership_admin`, `primary_owner`. Not validated against a fixed list here since the valid set is organization-type-dependent; an invalid value is rejected by the API at apply time. Immutable after creation — changing this forces a new resource.

### Optional

- `rbac_group_ids` (Set of String) IDs of the RBAC groups (`rbac_group_...`, e.g. `anthropic_rbac_group.example.id`) the person joins when they accept the invite, granting them the permissions of the custom roles attached to those groups. At most 100. Claude Enterprise only: a non-empty set requires a Claude Enterprise scoped Admin API key, created for all linked organizations, carrying `write:rbac_groups` in addition to `write:members`. The membership of a group provisioned by the identity provider (`source_type = "scim"`) is managed in the identity provider. Read back from the API on refresh. Changing it forces a new resource (a new invitation email), except switching between unset and an empty set, which both mean no group.

### Read-Only

- `accepted_at` (String) RFC 3339 timestamp of when the invite was accepted, or empty if it has not been accepted.
- `expires_at` (String) RFC 3339 timestamp of when the invite expires.
- `id` (String) Unique invite identifier assigned by the API.
- `invited_at` (String) RFC 3339 timestamp of when the invite was sent.
- `status` (String) Status of the invite: `pending`, `accepted`, `expired`, or `deleted`.
- `type` (String) Object type. Always `invite`.

## Import

Import an existing invite using its ID:

```shell
terraform import anthropic_invite.example <invite_id>
```
