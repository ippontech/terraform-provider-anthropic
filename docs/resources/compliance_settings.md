# anthropic_compliance_settings (Resource)

Turns the organization's [Compliance API](https://platform.claude.com/docs/en/manage-claude/compliance-api) on or off via the Admin API: the same switch as the **Compliance API** toggle on the Claude Console's [Compliance](https://platform.claude.com/settings/security) page. While it is enabled, organization activity is recorded for the [Activity Feed](https://platform.claude.com/docs/en/manage-claude/compliance-activity-feed).

The settings are an organization-wide singleton for the organization of the configured admin key. Declare the resource once per organization. The resource records that organization's ID, and a refresh or an apply fails if the configured admin key later belongs to another organization, rather than switching that organization's Compliance API.

> **API**: `GET/POST /v1/organizations/compliance_settings` (Admin API).
> **Auth**: Admin API key (`admin_api_key` / `ANTHROPIC_ADMIN_API_KEY`).
> **Beta header**: None.
> **Cost**: Free.

## Behavior

- **Create** adopts the existing settings and applies `state`. The update is idempotent, so adopting settings already in that state changes nothing.
- **Destroy leaves the Compliance API as it is** and only removes the resource from the Terraform state, with a warning. Turning the Compliance API off stops activity recording (and Access Transparency event delivery), and activity missed while it is off can never be recovered, so the provider never does it implicitly. To turn it off, set `state = "disabled"` and apply before removing the resource.
- **Access Transparency re-enables it.** A `disabled` setting stays in effect until a later `enabled`, or until a provisioning action that enables [Access Transparency](https://platform.claude.com/docs/en/manage-claude/access-transparency) for the organization, which turns the Compliance API back on, re-runs included. With `state = "disabled"`, the next plan then shows an update back to `disabled`. If Access Transparency should decide, set `state = "enabled"`, or add `lifecycle { ignore_changes = [state] }`.
- **Linked organizations inherit the setting.** An organization with a parent organization reads the state of the parent's configuration, which the parent's primary owner manages in claude.ai. Manage this resource for standalone Claude Console organizations. If the API answers an update with another state than the one sent, the apply fails with an error that says so.
- An Admin API key gets the `read:compliance_activities` scope only if the Compliance API was enabled when the key was created. After enabling it, create a new Admin API key to read the Activity Feed ([key types](https://platform.claude.com/docs/en/manage-claude/compliance-api-access#which-key-do-you-need)).

## Example Usage

```hcl
# Turn on the Compliance API and its activity recording for the organization of
# the admin key. Destroying this resource leaves the setting as it is.
resource "anthropic_compliance_settings" "this" {
  state = "enabled"
}

output "compliance_api_state" {
  description = "Whether the Compliance API is enabled for the organization."
  value       = anthropic_compliance_settings.this.state
}
```

## Schema

### Required

- `state` (String) `enabled` turns on the Compliance API and starts recording organization activity events; `disabled` turns both off. Activity that happens while it is disabled is never recorded. An Access Transparency provisioning re-enables it after a `disabled`, which the next plan reports as drift.

### Read-Only

- `id` (String) ID of the organization the settings belong to: the organization of the configured admin key.

## Import

The settings are addressed through the admin key's organization, not by ID, so any import ID works; by convention, pass the organization ID. The imported `id` is always the organization ID read from the API, and an import ID that differs from it gets a warning naming the organization imported.

```shell
terraform import anthropic_compliance_settings.this <organization_id>
```
