# anthropic_user_profile (Data Source)

Fetches a single user profile by ID (beta). A user profile represents an end-user or resold-to company on whose behalf the API is used.

-> This beta is not generally available. As of 2026-09-30 the endpoint returns `404` for organizations that have not been enrolled.

> **API**: `GET /v1/user_profiles/{id}` (beta).
> **Auth**: Standard API key (`api_key` / `ANTHROPIC_API_KEY`).
> **Beta header**: `user-profiles-2026-08-18`.

## Example Usage

```hcl
data "anthropic_user_profile" "example" {
  id = "uprof_01AAAAAAAAAAAAAAAAAAAAAA"
}

output "user_profile_id" {
  description = "ID of the user profile."
  value       = data.anthropic_user_profile.example.id
}

output "user_profile_access_type" {
  description = "Access type of the user profile (`application` or `passthrough`)."
  value       = data.anthropic_user_profile.example.access_type
}

output "user_profile_name" {
  description = "Real-world name of the entity the user profile represents."
  value       = data.anthropic_user_profile.example.name
  sensitive   = true
}
```

### Read-Only

- `access_type` (String) How the platform uses the API on behalf of the entity this profile represents. `application`: the platform sells a product that uses the API behind the scenes, and the profile represents an individual end-user of that product. `passthrough`: the platform resells raw inference, and the profile identifies the resold-to company.

- `trust_grants` (Map of Object) Trust grants for this profile, keyed by grant name. A grant name is absent from the map when it has no active or in-flight grant. Each entry has a `status` (`active`, `pending`, or `rejected`). (see [below for nested schema](#nestedatt--trust_grants))
