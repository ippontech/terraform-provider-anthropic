# anthropic_claude_code_routine_fire (Action)

Starts a run of an existing [Claude Code routine](https://code.claude.com/docs/en/routines) through its API trigger, for example to run an agent after an apply. A routine is a saved Claude Code configuration (prompt, repositories, connectors) created at [claude.ai/code/routines](https://claude.ai/code/routines); it is a Claude Code product, not a Managed Agents `anthropic_deployment`.

Each invocation creates a new Claude Code session and reports its URL as progress output. The endpoint has no idempotency key, so the action never retries a fire: a failed request is reported as an error, and a network error or 5xx may still have started the routine.

> **API**: `POST /v1/claude_code/routines/{routine_id}/fire` (Claude Code, [experimental](https://platform.claude.com/docs/en/api/claude-code/routines-fire)).
> **Auth**: The routine's own bearer token (`token`), not the provider's credentials. The provider still needs one of its credentials to configure.
> **Requires**: Terraform 1.14 or later; a claude.ai Pro, Max, Team or Enterprise plan with Claude Code on the web.
> **Limits**: 30 fires per routine and 100 API fires per account per hour.
> **Cost**: Each run draws on the claude.ai subscription's Claude Code usage.

## Before you begin

Routines and their tokens can only be created in the web UI: open the routine for editing, add an **API** trigger and click **Generate token**. The dialog shows the routine's URL, which contains its ID (`trig_...`), and the token, which is shown once. Generating a new token revokes the previous one.

The routine receives `text` wrapped as untrusted data, so its saved prompt must say what to do with it.

## Example Usage

```hcl
variable "routine_id" {
  description = "ID of the Claude Code routine to fire (trig_...), from its API trigger URL."
  type        = string
}

variable "routine_token" {
  description = "The routine's API trigger token (sk-ant-oat01-...)."
  type        = string
  sensitive   = true
}

variable "release" {
  description = "Version being deployed; a new value fires the routine again."
  type        = string
  default     = "1.0.0"
}

# Starts a run of the routine. Each invocation creates a new Claude Code session.
action "anthropic_claude_code_routine_fire" "after_deploy" {
  config {
    routine_id = var.routine_id
    token      = var.routine_token
    text       = "Release ${var.release} was applied. Run the smoke checks described in your prompt."
  }
}

# Fires the routine after the release is first applied and on every change.
resource "terraform_data" "release" {
  input = var.release

  lifecycle {
    action_trigger {
      events  = [after_create, after_update]
      actions = [action.anthropic_claude_code_routine_fire.after_deploy]
    }
  }
}
```

To fire the routine outside a lifecycle event:

```shell
terraform apply -invoke=action.anthropic_claude_code_routine_fire.after_deploy
```

## Schema

### Required

- `routine_id` (String) The routine's ID, prefixed `trig_`. It is part of the URL the routine's API trigger dialog shows (`https://api.anthropic.com/v1/claude_code/routines/<routine_id>/fire`).
- `token` (String) The routine's API trigger bearer token (`sk-ant-oat01-...`), generated in the routine's API trigger dialog at claude.ai/code/routines. It is scoped to this routine and shown only once. Action configuration is never stored in state, but action schemas cannot mark an attribute sensitive, so pass the token through a `sensitive` variable to keep it out of plan output. Ephemeral values are not accepted: Terraform allows them only in write-only attributes, which actions do not support.

### Optional

- `text` (String) Run-specific context passed to the routine alongside its saved prompt, such as an alert body or a git diff. Freeform and not parsed. The routine receives it wrapped as untrusted data, so its saved prompt must say what to do with it. At most 65,536 characters.
