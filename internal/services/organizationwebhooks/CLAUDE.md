# `internal/services/organizationwebhooks/` service notes

Load-bearing details for `internal/services/organizationwebhooks/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_organization_webhook` (`internal/services/organizationwebhooks/organization_webhook_resource.go`) — manages an organization webhook endpoint (enforcement-action events on user profiles; Admin API `/v1/organizations/webhooks[/{id}]`, beta `webhooks-2026-10-07` sent on every request, 404 without it or when the per-organization beta is off; unavailable with HIPAA readiness; 32 endpoints per organization). `signing_secret` (Computed, Sensitive) follows the returned-once convention below: captured from the create response, kept by `Read` (null after import), regenerated through `POST …/{id}/regenerate_signing_secret` when `signing_secret_version` changes to a new non-null value (`signingSecretPlanModifier` plans the state value otherwise, so an import shows no spurious diff); `enabled` maps `state` (default `true`; create has no `state`, so a create response whose `state` differs from the plan, `enabled = false` or an endpoint created disabled, gets a second call, and a create that still differs fails with the endpoint saved); `name`/`description` are Optional+Computed with `UseStateForUnknown` and `""` → null via `tfvalue.StringOrNull`; `enabled_events` is a set validated against `organizationWebhookEventTypes` (the one list to extend); Update sends only changed fields, updates before regenerating, and on a failed regeneration saves the landed update with the old secret and version so the next plan retries (an error path that sets nothing keeps the prior state: framework v1.19.0 pre-populates `UpdateResponse.State` from it). Every write (any method but GET) holds the package-level `organizationWebhookWrites` mutex: the guide documents a 409 for concurrent changes to an organization's endpoints, and the Admin client does not replay a POST after a 409. A 404 on Read or Delete counts as deleted only when `GET /v1/organizations/webhooks?limit=1` answers (`organizationWebhooksUnavailable`): the whole API answers 404 when the organization loses the beta, and dropping the endpoint would lose its signing secret.
