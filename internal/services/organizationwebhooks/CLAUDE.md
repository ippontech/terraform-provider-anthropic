# Organization webhooks service notes

Load-bearing details for `internal/services/organizationwebhooks/`: the `anthropic_organization_webhook` resource (Admin API, raw `admin.Client`, beta header `webhooks-2026-10-07` on every call via `doOrganizationWebhookRequest`, Admin key). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_organization_webhook` (`internal/services/organizationwebhooks/organization_webhook_resource.go`) — manages an organization webhook endpoint (enforcement-action events on user profiles; Admin API `/v1/organizations/webhooks[/{id}]`, beta `webhooks-2026-10-07` sent on every request, 404 without it or when the per-organization beta is off; unavailable with HIPAA readiness; 32 endpoints per organization). `signing_secret` (Computed, Sensitive) follows the returned-once convention (root `CLAUDE.md`, "Secrets the API returns once"): captured from the create response, kept by `Read` (null after import), regenerated through `POST …/{id}/regenerate_signing_secret` when `signing_secret_version` changes to a new non-null value (`signingSecretPlanModifier` plans the state value otherwise, so an import shows no spurious diff); `enabled` maps `state` (default `true`; create has no `state`, so `enabled = false` is a second call); `name`/`description` are Optional+Computed with `UseStateForUnknown` and `""` → null via `tfvalue.StringOrNull`; `enabled_events` is a set validated against `organizationWebhookEventTypes` (the one list to extend); Update sends only changed fields, updates before regenerating, and on a failed regeneration saves the landed update with the old secret and version so the next plan retries. No live test (#58, beta on request): httptest unit tests (beta header asserted on every call) + `command = plan` native test
