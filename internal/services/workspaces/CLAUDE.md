# Workspaces service notes

Load-bearing details for `internal/services/workspaces/`: the `anthropic_workspace` and `anthropic_workspace_member` resources and the `anthropic_workspace(s)`, `anthropic_workspace_member(s)` and `anthropic_workspace_rate_limits` data sources (Admin API, `internal/admin` client). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_workspace` (`internal/services/workspaces/workspace_resource.go`) — manages workspaces (admin API; update is `POST /v1/organizations/workspaces/{id}`). Beyond `name`/`data_residency`: `tags` (map, Optional+Computed; keys starting with `anthropic` rejected at plan time, case-insensitive; update sends planned keys plus `null` for every key present in state and absent from the plan via `buildWorkspaceTagsPatch`, and omits `tags` when unchanged; measured live on 2026-10-08 (reversible probe on `terraform-tests`): the API **merges** tags, a per-key `null` deletes the key, `{}` is a **no-op** (so `tags = {}` must send `null` for each prior key), a whole-map `null` is a 400 ("At least one field must be provided") and an `anthropic`-prefixed key is rejected server-side with a 400 too; omitting the attribute keeps the server's tags, `tags = {}` clears them), `external_key_id` (CMEK `ekey_…`, write-once: Optional+Computed with `UseStateForUnknown` **then** `RequiresReplaceIf` (`externalKeyRequiresReplace`: only when an attached key changes or is removed), so a key attached from the Console does not force a destructive replace and attaching a first key to an existing workspace is an in-place update, since the Update reference lists `external_key_id` as a body parameter; sent on update only when state is null and the plan sets it, via `buildWorkspaceExternalKeyUpdate`), and Computed `compartment_id`, `user_profile_id`, `inference_data_retention{type}`. The last two exist only in the live payload (probed 2026-10-08, only `{"type": "disabled"}` observed): neither the SDK v1.67.0 `BetaWorkspace` type nor the reference pages list them, so the object is decoded leniently and documented as observed, not specified. Same five attributes are Computed on the `workspace`/`workspaces` data sources. A state created before these attributes existed plans `No changes` with the new schema (checked with an import under the old binary, then a plan under the new one)
- `anthropic_workspace_member` (`internal/services/workspaces/workspace_member_resource.go`) — assigns a user to a workspace with a given role (admin API); composite ID `<workspace_id>:<user_id>`; `workspace_billing` role rejected at plan time

**Data sources:**
- `anthropic_workspace` (`internal/services/workspaces/workspace_data_source.go`) — fetches a single workspace by ID (admin API)
- `anthropic_workspaces` (`internal/services/workspaces/workspaces_data_source.go`) — lists all workspaces (admin API, transparent pagination)
- `anthropic_workspace_member` (`internal/services/workspaces/workspace_member_data_source.go`) — fetches a single workspace member by workspace ID and user ID (admin API)
- `anthropic_workspace_members` (`internal/services/workspaces/workspace_members_data_source.go`) — lists all members of a workspace (admin API), with transparent pagination
- `anthropic_workspace_rate_limits` (`internal/services/workspaces/workspace_rate_limits_data_source.go`) — lists workspace-level rate-limit overrides for a workspace (admin API), with transparent pagination and an optional `group_type` filter; only entries with at least one override are returned
