# `internal/services/spendlimits/` service notes

Load-bearing details for `internal/services/spendlimits/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_spend_limit` (`internal/services/spendlimits/spend_limit_resource.go`) — a cap on metered spend for one (`scope`, `period`) pair (raw `admin.Client`; Enterprise scoped key with `read:`/`write:spend_limits`); `POST /v1/organizations/spend_limits` is an **upsert** on that pair, so Create **adopts** an existing limit (documented) and Update re-posts the same pair with the new amount; `scope {type, user_id|workspace_id}` and `period` (Optional+Computed, default `monthly`, `daily`/`weekly`/`monthly`) are `RequiresReplace`; writable scope types are `user` (Enterprise) and `organization`/`workspace` (Console early access), anything else is a 400; `amount` is a decimal string in minor units (regex without leading zeros so it reads back as written), and a null `amount` is sent as JSON `null`, the explicit no-limit override (`organization`/`workspace` limits are monthly and need an amount: `spendLimitConfigValidator`, Unknown-tolerant); `is_enabled`, `currency` Computed; `id` and `created_at` have no `UseStateForUnknown`, since an amount change re-posts the upsert, which re-creates a limit deleted since the refresh under a new ID; Delete tolerates 404, and leaves in place (warning) a limit whose ID a set wrote during the same apply (`spend_limit_writes.go`: per-client record of set IDs plus a lock per (`scope`, `period`) pair), since the upsert keeps the ID and a shrinking `count` or a `create_before_destroy` replacement would otherwise delete the cap another instance has just set. Every spend limit call carries `?beta=true`, as the SDK does, and no `anthropic-beta` header (only the list endpoint, unused here, needs `spend-limit-reads-2026-09-26`). Acceptance tests are gated on `ANTHROPIC_SPEND_LIMITS_ACC=1` on top of `acctest.PreCheckAdmin` (the test org has neither Enterprise nor the Console preview); the native test is `command = plan`
