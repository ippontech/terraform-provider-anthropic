# Spend limits service notes

Load-bearing details for `internal/services/spendlimits/`: anthropic_spend_limit resource (raw `admin.Client`, SDK has them only from v1.77.0; Claude Enterprise `user` limits, Console `organization`/`workspace` limits in early access). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_spend_limit` (`internal/services/spendlimits/spend_limit_resource.go`) — a cap on metered spend for one (`scope`, `period`) pair (raw `admin.Client`; Enterprise scoped key with `read:`/`write:spend_limits`); `POST /v1/organizations/spend_limits` is an **upsert** on that pair, so Create **adopts** an existing limit (documented) and Update re-posts the same pair with the new amount; `scope {type, user_id|workspace_id}` and `period` (Optional+Computed, default `monthly`, `daily`/`weekly`/`monthly`) are `RequiresReplace`; writable scope types are `user` (Enterprise) and `organization`/`workspace` (Console early access), anything else is a 400; `amount` is a decimal string in minor units (regex without leading zeros so it reads back as written), and a null `amount` is sent as JSON `null`, the explicit no-limit override (`organization`/`workspace` limits are monthly and need an amount: `spendLimitConfigValidator`, Unknown-tolerant); `is_enabled`, `currency` Computed; Delete tolerates 404. Every spend limit call carries `?beta=true`, as the SDK does. Acceptance tests are gated on `ANTHROPIC_SPEND_LIMITS_ACC=1` on top of `acctest.PreCheckAdmin` (the test org has neither Enterprise nor the Console preview); the native test is `command = plan`
