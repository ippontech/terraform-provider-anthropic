# API keys service notes

Load-bearing details for `internal/services/apikeys/`: the import-only `anthropic_api_key` resource and the `anthropic_api_key` / `anthropic_api_keys` data sources (Admin API, `internal/admin` client). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_api_key` (`internal/services/apikeys/api_key_resource.go`) — import-only resource; manages lifecycle of existing API keys (rename, deactivate) via Admin API; Create always errors with a message to use `terraform import`; Delete sets `status: inactive`. Computed `expires_at`, `scope{type, workspace_id}` and `principal{type, user_id, service_account_id}` (null for legacy keys); `partial_key_hint` maps to null when the API sends null, and `created_by` to an object with a null `id` and `type` (never a null object: existing configurations read `created_by.id`); Update keeps a pre-upgrade empty `created_by`/`partial_key_hint` that `-refresh=false` planned (`keepLegacyEmptyValues`), and `scope`/`principal`/`expires_at` use `stateUnlessPreUpgrade`: the prior value, a real null included (no expiry, legacy key without principal), is planned as `UseStateForUnknown` would, except over a state written before they existed (told apart by a null `scope`, which the API always sends), where they stay unknown for Update to fill (in framework v1.19.0 `UseStateForUnknown` copies a null state value). `status` is validated against the update endpoint's `active`/`inactive`/`archived`; the API's `expired` is read-only and only ever comes from Read. `workspace_id` carries the provider's first `DeprecationMessage` (`apiKeyWorkspaceIDDeprecation`, shared with both data sources): null for organization-scoped and Default Workspace keys, removed in API version 2026-10-21, which `internal/admin` does not send (it pins 2023-06-01)

**Data sources:**
- `anthropic_api_key` (`internal/services/apikeys/api_key_data_source.go`) — fetches a single API key by ID (admin API); reuses `APIKeyResourceModel` and `mapAPIKeyToState` from the resource file
- `anthropic_api_keys` (`internal/services/apikeys/api_keys_data_source.go`) — lists API keys (admin API) with optional `status` (`expired` included), `workspace_id` and `created_by_user_id` filters; transparent pagination; list items are `mapAPIKeyToState` output converted with `types.ObjectValueFrom`, so `apiKeyListItemAttrTypes` must match the resource schema (pinned by `TestAPIKeyListItemAttrTypes_matchResourceSchema`)
