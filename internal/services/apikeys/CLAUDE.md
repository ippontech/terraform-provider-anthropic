# API keys service notes

Load-bearing details for `internal/services/apikeys/`: the import-only `anthropic_api_key` resource and the `anthropic_api_key` / `anthropic_api_keys` data sources (Admin API, `internal/admin` client). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_api_key` (`internal/services/apikeys/api_key_resource.go`) — import-only resource; manages lifecycle of existing API keys (rename, deactivate) via Admin API; Create always errors with a message to use `terraform import`; Delete sets `status: inactive`. Computed `expires_at`, `scope{type, workspace_id}` and `principal{type, user_id, service_account_id}` (null when the API sends none); `created_by.id`, `created_by.type` and `partial_key_hint` keep mapping to `""` (see *Deferred to 2.0.0* below). `scope`/`principal`/`expires_at` use `stateUnlessPreUpgrade`: the prior value, a real null included (no expiry, legacy key without principal), is planned as `UseStateForUnknown` would, except over a state written before they existed (told apart by a null `scope`, which the API always sends), where they stay unknown for Update to fill (in framework v1.19.0 `UseStateForUnknown` copies a null state value). `status` accepts every status the API reports (`apiKeyStatuses`, `expired` included: `terraform plan -generate-config-out` copies an expired key's `status` into the generated configuration), and the `rejectExpiredStatusChange` plan modifier fails a plan that sets `expired` over a prior state holding another value or none (a create); the API's `expired` is read-only and only ever comes from Read, so Update (`apiKeyStatusToSend`) sends `status` only when the configuration sets it (an unset `status` plans the state value, `expired` included, and renaming an expired key must not send it back), and then sends the **planned** value, never the one read from `req.Config`: `ignore_changes = [status]` plans the state value while the configuration still says `active`, and sending the configuration would switch back on a key deactivated outside Terraform. It is sent even when it equals state (over a stale state, `-refresh=false` or a saved plan, a key deactivated outside Terraform would otherwise come back `inactive` and fail the apply as an inconsistent result), except a planned value the endpoint does not accept (an `expired` kept from state, configured or under `ignore_changes`), which is left out. `workspace_id` carries a `DeprecationMessage` (`apiKeyWorkspaceIDDeprecation`, shared with both data sources; Terraform 1.16 and 1.17 warn on a reference to the resource's or the single data source's `workspace_id`, never on one through the `api_keys` list, so the list page carries a callout instead): null for organization-scoped and Default Workspace keys, removed in API version 2026-10-21, which `internal/admin` does not send (it pins 2023-06-01)

**Data sources:**
- `anthropic_api_key` (`internal/services/apikeys/api_key_data_source.go`) — fetches a single API key by ID (admin API); reuses `APIKeyResourceModel` and `mapAPIKeyToState` from the resource file
- `anthropic_api_keys` (`internal/services/apikeys/api_keys_data_source.go`) — lists API keys (admin API) with optional `status` (`expired` included), `workspace_id` and `created_by_user_id` filters; transparent pagination (`listAPIKeys`, `after_id`/`has_more`/`last_id`: a `last_id` already sent, an empty one included, or more than `sdkpage.MaxPages` pages is an error instead of a loop); list items are `mapAPIKeyToState` output converted with `types.ObjectValueFrom`, so `apiKeyListItemAttrTypes` must match the resource schema (pinned by `TestAPIKeyListItemAttrTypes_matchResourceSchema`)

**Deferred to 2.0.0:**
- `created_by.id`, `created_by.type` and `partial_key_hint` map to `""` when the API sends none (`"created_by": null` decodes into the value struct `apiKeyCreatedBy`, and `created_by` is never a null object), on the resource, the `anthropic_api_key` data source and every `anthropic_api_keys` item. Switching them to null would break a configuration that passes them to a string function or compares them with `""`, so it waits for 2.0.0 (maintainer decision on #431). The `*LegacyKey*` / `*legacyKey*` tests pin `""`; the new `expires_at`, `scope` and `principal` map to null.
