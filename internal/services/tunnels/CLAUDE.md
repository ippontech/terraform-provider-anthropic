# Tunnels service notes

Load-bearing details for `internal/services/tunnels/`: MCP tunnels (research preview, no deprecation period): the `anthropic_tunnel` and `anthropic_tunnel_certificate` resources and the `anthropic_tunnel`, `anthropic_tunnels` and `anthropic_tunnel_certificates` data sources (`client.Beta.Tunnels` / `client.Beta.Tunnels.Certificates`, workspace-scoped `/v1/tunnels`, never the deprecated `/v1/organizations/tunnels`; beta header `mcp-tunnels-2026-06-22` sent by the SDK; `pd.OAuthClient` carrying a `workspace:manage_tunnels` token, API keys rejected). Unavailable on Claude Platform on AWS and Claude Models on Google Cloud (`internal/provider/registry.go`): their gateways accept no Anthropic OAuth token. The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_tunnel` (`internal/services/tunnels/tunnel_resource.go`) — manages an MCP tunnel (`tnl_...`; research preview, no deprecation period). **Auth is the exception among workspace-scoped APIs**: the Tunnels API rejects API keys and takes an OAuth bearer with the `workspace:manage_tunnels` scope (WIF rule created in the Console), so it uses `pd.OAuthClient` like the WIF resources; one provider block carries one bearer, hence an aliased provider block in the docs. No update or delete endpoint: `display_name` is `RequiresReplace` (new domain) and destroy always archives (irreversible: archives its certificates, retires the domain, invalidates the token; a 404 or an already-archived tunnel is fine). `Read` drops a tunnel archived out of band (`RemoveResource`) so the next apply re-provisions one. `New` is called with `option.WithMaxRetries(0)`: creation is not idempotent and the SDK would replay the POST on 409/5xx/dropped connections, each duplicate holding one of the org's 10 active-tunnel slots. Only a 429, which states the request was not processed, is sent again, by `retry.CreateRetrying429` (`internal/retry/create_429.go`, shared with `anthropic_webhook`: 2 retries, `retry-after-ms`/`retry-after` honored up to 60 s; `x-should-retry: false` vetoes the retry, and `x-should-retry: true` never makes another status retryable, unlike the SDK and `internal/admin`'s `shouldRetry`); the certificate registration goes through it too, since a replacement has already archived the old CA when its create runs. Token design: `token` is Computed + Sensitive (stored in state), revealed once in `Create` (a reveal failure still saves the tunnel, so Terraform taints it; the error names `terraform untaint` to keep it, after which `Update` reveals the token) and, when state has none (after an import), once in `Update`, **never on plan or refresh**, because every `reveal_token` is a `tunnel_token_revealed` compliance event and a plan never saves its refreshed state, so a pending `import` block would reveal on every plan: `Read` never reveals, and `tokenPlan` plans `token`/`token_id` unknown when state has no token, so the plan after an import shows an update and its apply reveals (a reveal or rotation failure there is an error that keeps the prior state, since the framework starts the update response from it, so the next plan asks again; covered end to end by `TestTunnelResource_importThenPlanAndApply` and `TestTunnelResource_rotateFailureKeepsPriorState` through `providerserver`); `token_rotation` (Optional string, like the setup component's `--token-version`) calls `rotate_token` only when it changes between two non-null values (`tokenRotationRequested`: a first value or a removal never rotates, so importing with it set does not break the running connector); `token`/`token_id` use `tokenPlan` (null with `store_token = false`; otherwise the state value unless a rotation is planned or state has no token, unknown then). An out-of-band rotation is not detected (documented). `store_token` (Optional + Computed bool, `Default` true; `Read` sets true when null, since the API does not hold it) keeps the token out of state for a connector that fetches it itself: with `false`, nothing calls `reveal_token` (not `Create`, not after an import, not `Update`), `token`/`token_id` are planned and stored null, and a `token_rotation` change still calls `rotate_token` but discards the new value (`token_id` too, so the provider never shows a token it does not hold). Turning it false clears the stored token at the next apply with no API call; turning it back true plans the missing token unknown and `Update` reveals it, the same path as an import (`TestTunnelResource_Update_storeToken`, `TestTunnelResource_importWithoutStoringToken`)
- `anthropic_tunnel_certificate` (`internal/services/tunnels/tunnel_certificate_resource.go`) — registers a CA certificate (`tcrt_...`) on a tunnel; composite import ID `<tunnel_id>:<certificate_id>`; destroy archives (404 tolerated); `Read` drops an archived certificate; `New` retried only on a 429, through `retry.CreateRetrying429` (at most 2 non-archived certificates per tunnel, so any other failure is never replayed). The API never returns the PEM, so `ca_certificate_pem` (Required, local `caCertificatePEMValidator`: ≤ 8192 bytes, exactly one `CERTIFICATE` block, no other block and no further `-----BEGIN` marker even unparsable, no `PRIVATE KEY` text anywhere) is compared by DER SHA-256 against the state `fingerprint` (`caCertificateChanged`, a `RequiresReplaceIf`; both sides go through `normalizeFingerprint`, which drops case, a `sha256:` prefix and colons, since the wire format was never checked live; the resource and `anthropic_tunnel_certificates` also store `fingerprint` in that form): same certificate re-wrapped, or the first plan after an import, goes through a no-API `Update`; anything else, unknown or unparsable replaces. The example reads `ca.crt`, not `ca.pem`, because `.gitignore` ignores `*.pem`

**Data sources:**
- `anthropic_tunnel` (`internal/services/tunnels/tunnel_data_source.go`) — fetches a tunnel by ID, archived or not (`archived_at` exposed); never exposes the token (revealing is audited)
- `anthropic_tunnel_certificates` (`internal/services/tunnels/tunnel_certificates_data_source.go`) — lists a tunnel's CA certificates (`GET /v1/tunnels/{tunnel_id}/certificates`, `limit=100`, pages walked with `sdkpage.Cursor`; order not documented, kept as returned); `include_archived` sent only when true (false is the API default); an empty result is an empty list, as for `anthropic_tunnels`; no PEM (the API never returns it), `fingerprint` identifies each certificate
- `anthropic_tunnels` (`internal/services/tunnels/tunnels_data_source.go`) — lists the credential's workspace tunnels (newest first, `limit=100`, pages walked with `sdkpage.Cursor`, not `ListAutoPaging`, so a repeated `next_page` cursor fails the read instead of looping) with optional `include_archived`; no token. Tunnel acceptance tests (all five) are gated on `acctest.PreCheckOAuth` **plus** an explicit `ANTHROPIC_TUNNELS_ACC=1` opt-in (`preCheckTunnelsAcc`, `helpers_test.go`): CI has no `workspace:manage_tunnels` token, the local org:admin token has the wrong scope, the preview must be granted, and every run leaves archived tunnels; native tests are `command = plan` with a dummy `auth_token` (resources) or `mock_provider` (data sources)
