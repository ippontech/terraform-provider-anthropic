# `internal/services/tunnels/` service notes

Load-bearing details for `internal/services/tunnels/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_tunnel` (`internal/services/tunnels/tunnel_resource.go`) — manages an MCP tunnel (`tnl_...`; research preview, no deprecation period). **Auth is the exception among workspace-scoped APIs**: the Tunnels API rejects API keys and takes an OAuth bearer with the `workspace:manage_tunnels` scope (WIF rule created in the Console), so it uses `pd.OAuthClient` like the WIF resources; one provider block carries one bearer, hence an aliased provider block in the docs. No update or delete endpoint: `display_name` is `RequiresReplace` (new domain) and destroy always archives (irreversible: archives its certificates, retires the domain, invalidates the token; a 404 or an already-archived tunnel is fine). `Read` drops a tunnel archived out of band (`RemoveResource`) so the next apply re-provisions one. `New` is called with `option.WithMaxRetries(0)`: creation is not idempotent and the SDK would replay the POST on 409/5xx/dropped connections, each duplicate holding one of the org's 10 active-tunnel slots. Token design: `token` is Computed + Sensitive (stored in state), revealed once in `Create` (a reveal failure still saves the tunnel so Terraform taints it) and once in `Read` when state has none (import; a failure there is only a warning, so it cannot block the plan that replaces a tainted tunnel), **never on refresh**, because every `reveal_token` is a `tunnel_token_revealed` compliance event; `token_rotation` (Optional string, like the setup component's `--token-version`) calls `rotate_token` only when it changes between two non-null values (`tokenRotationRequested`: a first value or a removal never rotates, so importing with it set does not break the running connector); `token`/`token_id` use `tokenFollowsRotation` (state value unless a rotation is planned). An out-of-band rotation is not detected (documented)
- `anthropic_tunnel_certificate` (`internal/services/tunnels/tunnel_certificate_resource.go`) — registers a CA certificate (`tcrt_...`) on a tunnel; composite import ID `<tunnel_id>:<certificate_id>`; destroy archives (404 tolerated); `Read` drops an archived certificate; `New` not retried (at most 2 non-archived certificates per tunnel). The API never returns the PEM, so `ca_certificate_pem` (Required, local `caCertificatePEMValidator`: ≤ 8192 bytes, exactly one `CERTIFICATE` block, no other block) is compared by DER SHA-256 against the state `fingerprint` (`caCertificateChanged`, a `RequiresReplaceIf`): same certificate re-wrapped, or the first plan after an import, goes through a no-API `Update`; anything else, unknown or unparsable replaces. The example reads `ca.crt`, not `ca.pem`, because `.gitignore` ignores `*.pem`

**Data sources:**
- `anthropic_tunnel` (`internal/services/tunnels/tunnel_data_source.go`) — fetches a tunnel by ID, archived or not (`archived_at` exposed); never exposes the token (revealing is audited)
- `anthropic_tunnels` (`internal/services/tunnels/tunnels_data_source.go`) — lists the credential's workspace tunnels (newest first, transparent pagination, `limit=100`) with optional `include_archived`; no token. Tunnel acceptance tests (all four) are gated on `acctest.PreCheckOAuth` **plus** an explicit `ANTHROPIC_TUNNELS_ACC=1` opt-in (`preCheckTunnelsAcc`, `helpers_test.go`): CI has no `workspace:manage_tunnels` token, the local org:admin token has the wrong scope, the preview must be granted, and every run leaves archived tunnels; native tests are `command = plan` with a dummy `auth_token` (resources) or `mock_provider` (data sources)
