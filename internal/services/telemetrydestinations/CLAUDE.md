# `internal/services/telemetrydestinations/` service notes

Load-bearing details for `internal/services/telemetrydestinations/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_telemetry_destination` (`internal/services/telemetrydestinations/telemetry_destination_resource.go`) — manages an OpenTelemetry destination (OTLP/HTTP export of Messages API and Managed Agents traces; Admin API `/v1/organizations/telemetry_destinations[/{id}]`, beta `telemetry-destinations-2026-08-11` on every request; 10 per organization). `headers_wo` (write-only map, Sensitive) + `headers_wo_version` follow the write-only convention: `telemetryDestinationConfigValidator` requires the version with headers (and rejects names differing only in case, and `workspace_ids` with type `all`); Update re-sends the configured headers on every update, which also covers a version bump and an `endpoint_url` hostname/port change (the API then wipes every header), always with `endpoint_url` (required by the API with header values); `buildHeadersPatch` sends `null` for each name in the Computed `header_names` from state that the config dropped, and reuses the registered spelling of a name matched case-insensitively, so a re-send never renames a header behind `header_names`; a null `headers_wo` leaves headers unmanaged (import), `{}` removes them. `headerNamesPlanModifier` plans state unless the configured names differ case-insensitively or the host/port changes (unknown then, which makes out-of-band name drift an update; plan warning when unmanaged headers will be wiped). `workspaces` (`type` all/include/exclude, `workspace_ids` set of 1–100, the per-request cap) is sent whole when it changes, `[]` for an omitted list on update since an omitted `workspace_ids` keeps the stored list; reads return only `workspaces.type`, so Read lists `GET …/{id}/workspaces` (page/next_page) while Create/Update take the IDs from the plan (the request replaced the whole list, no read-after-write risk); the per-workspace add/remove endpoints are not used. `traces` is Optional+Computed with `UseStateForUnknown` (omitted = keep the API's values); its `content_mode`/`enabled` defaults come from `tracesDefaultString`/`tracesDefaultBool` plan modifiers that apply only when the block is configured, **not** schema `Default`s: the framework applies nested defaults inside the prior state's object when the whole block is omitted, which turned every plan into a spurious update (caught by a local terraform-plugin-testing run against a stateful fake). `traces.max_content_bytes` is Optional+Computed (`UseStateForUnknown`). With the block omitted and a stored `traces.endpoint_url`, an `endpoint_url` host/port change plans `traces` unknown (`tracesFollowEndpointHost`, plan warning) and Update sends `traces.endpoint_url: null` instead of replaying a URL on the old host, which the API requires to share host and port. `endpoint_url` and `traces.endpoint_url` keep the planned or stored spelling when the API returns the same URL up to scheme/host case, an explicit `:443` or a trailing slash (`sameURL`; normalization unverified live). `enabled` maps the `state` union (create has no state, so a create response whose state differs from the plan, `enabled = false` or a destination created disabled, gets a second call), `disabled_reason` is the disabled `reason.type`; a create or update left in another state than planned fails with the reason (`addEnabledMismatchError`), the API's values saved. Read drops the resource only on a 404 of the destination itself, not of its workspace list.
