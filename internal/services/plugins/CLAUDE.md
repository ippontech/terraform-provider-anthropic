# Plugins service notes

Load-bearing details for `internal/services/plugins/`: Claude Enterprise Plugins API (beta `ce-plugins-2026-09-01`, raw `admin.Client`, Enterprise scoped admin key): anthropic_plugin + anthropic_plugin_version resources; multipart bodies built in plugin_source.go, requests in plugin_requests.go; no acceptance tests (Console test org), httptest + plan only. The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_plugin` (`internal/services/plugins/plugin_resource.go`) — uploads a Claude Enterprise plugin and its first version (`POST /v1/organizations/plugins`, multipart `files[]` parts named by their path within the plugin, or one `.zip`/`.plugin` archive; body built with `mime/multipart` into `admin.RawBody`, since `provretry.MultipartUpload` prefixes a bundle directory and retries 5xx, which a non-idempotent upload must not); every request sends `admin.WithBeta("ce-plugins-2026-09-01")` plus `?beta=true` like the SDK (`pluginsRequest`). `source_dir`/`source_archive`/`release_notes` are **create-only**: a later change is an in-place no-op with a plan warning (`ModifyPlan`), so an imported plugin needs no source and an edit never destroys the plugin (destroy deletes every version and installation setting); new content goes through `anthropic_plugin_version`. `served_version_id` (Optional+Computed) is `POST /plugins/{id}`, which **pins** irreversibly: `ModifyPlan` plans `served_version_pinned = true` whenever it is configured, so an unpinned plugin already serving that version still gets the pinning update. A version resource cannot feed `served_version_id` (dependency cycle), documented. Create handles the two errors that carry a stored plugin's ID (`APIError.Details`): 503 `registration_pending` is completed by uploading the same files as a version of `details.plugin_id` (as the API documents; the create is never resent), 409 `plugin_name_taken` names the plugin to import
- `anthropic_plugin_version` (`internal/services/plugins/plugin_version_resource.go`) — uploads an immutable plugin version (`POST /plugins/{id}/versions`); every input `RequiresReplace`, plus `source_hash` recomputed at every plan by `pluginSourceHashModifier` (archive: its SHA-256, as `filesha256()`; directory: hash over sorted `path\0sha256` lines), so an edit forces a new version; Create rebuilds the body, and refuses to upload if its hash differs from the planned one. No per-version delete endpoint: Delete warns and forgets. No import (the local source cannot be recovered). A 503 `registration_pending` with `x-should-retry: true` is resent by `admin.DoRequest` itself, as the API asks
