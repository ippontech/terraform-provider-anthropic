# `internal/services/plugins/` service notes

Load-bearing details for `internal/services/plugins/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_plugin` (`internal/services/plugins/plugin_resource.go`) — uploads a Claude Enterprise plugin and its first version (`POST /v1/organizations/plugins`, multipart `files[]` parts named by their path within the plugin, Git metadata (`.git` directories and files, any depth) left out of the upload and of the hash, or one `.zip`/`.plugin` archive; body built with `mime/multipart` into `admin.RawBody`, since `provretry.MultipartUpload` prefixes a bundle directory and retries 5xx, which a non-idempotent upload must not); every request sends `admin.WithBeta("ce-plugins-2026-09-01")` plus `?beta=true` like the SDK (`pluginsRequest`). `source_dir`/`source_archive`/`release_notes` are **create-only**: a later change is an in-place no-op with a plan warning (`ModifyPlan`), so an imported plugin needs no source and an edit never destroys the plugin (destroy deletes every version and installation setting); new content goes through `anthropic_plugin_version`. `served_version_id` (Optional+Computed) is `POST /plugins/{id}`, which **pins** irreversibly: `ModifyPlan` plans `served_version_pinned = true` whenever it is configured (unknown while the value is unknown, since it may turn out null, and when it names the version an unpinned plugin already serves, since under `ignore_changes` that is the prior value, which Terraform puts in the plan's configuration but not in the apply's: Update pins only for the configuration it applies), so an unpinned plugin already serving that version still gets the pinning update; that plan leaves every computed value the serve returns unknown (`planServeResultUnknown`), since with no configured change the framework would plan them from state. A version resource cannot feed `served_version_id` (dependency cycle), documented. A create, a replacement included, cannot take `served_version_id` (it can only name a version of an existing plugin, 404 otherwise): `ModifyPlan` refuses a known value and `Create` an unknown one before uploading, since a served-version failure after the upload would taint the plugin and every later apply would delete and re-upload it. Uploads (`admin.RawBody`) go through `pluginsRequest` with a timeout sized for the body (`withUploadTimeout`, plugin_upload.go) instead of the admin client's 60 s, which a large upload on a slow link outlasts while the API still stores it. Create handles the two errors that carry a stored plugin's ID (`APIError.Details`): 503 `registration_pending` is completed by uploading the same files as a version of `details.plugin_id` (as the API documents; the create is never resent), 409 `plugin_name_taken` names the plugin to import
- `anthropic_plugin_version` (`internal/services/plugins/plugin_version_resource.go`) — uploads an immutable plugin version (`POST /plugins/{id}/versions`); every input `RequiresReplace`, plus `source_hash` recomputed at every plan by `pluginSourceHashModifier` (archive: its SHA-256, as `filesha256()`; directory: hash over sorted `path\0sha256` lines), so an edit forces a new version; Create rebuilds the body, and refuses to upload if its hash differs from the planned one. No per-version delete endpoint: Delete warns and forgets. No import (the local source cannot be recovered). A 503 `registration_pending` with `x-should-retry: true` is resent by `admin.DoRequest` itself, as the API asks
- `anthropic_plugin_installation_setting` (`internal/services/plugins/plugin_installation_setting_resource.go`) — who may use an organization-owned plugin: `POST|DELETE /plugins/{id}/installation_settings/{target}`, `target` = `organization` or an `rbac_group_` ID, ID `<plugin_id>:<target>` (import too); Create is an upsert (adopts a setting made in claude.ai); there is no single-setting GET, so Read pages the list filtered by `target_type` (`listPluginsPages`: only a null `next_page` ends a list, a page can be empty with a cursor) and removes the resource when the target is absent or the plugin 404s. The API asks for a plugin's setting writes to be sent one at a time (it can 503 concurrent ones), so `pluginSettingLocks` (a `sync.Map` of per-plugin mutexes in `plugin_requests.go`) serializes them within the provider process; `TestPluginInstallationSettingWrites_areSerializedPerPlugin` fails without it
- `anthropic_plugin_marketplace_settings` (`internal/services/plugins/plugin_marketplace_settings_resource.go`) — update-only: `POST /plugin_marketplaces/{id}` sets `default_installation_preference`; marketplaces are created/deleted in claude.ai, so Create adopts by ID and Delete warns and forgets (a default cannot be set back to null), same contract as `anthropic_api_key`
