# Messages service notes

Load-bearing details for `internal/services/messages/`: the `anthropic_message` resource and the `anthropic_count_tokens` data source (`client.Messages`, standard API key). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_message` (`internal/services/messages/message_resource.go`) — calls the Messages API; write-only, immutable (no read/update/delete). Inputs beyond `model`/`max_tokens`/`messages`/`system`/`temperature`: `stop_sequences`, `metadata.user_id`, `service_tier` (`auto`/`standard_only`), `inference_geo` (`us`/`global`), `thinking` (`enabled` with `budget_tokens`, `disabled`, `adaptive`, optional `display`), `output_config` (`effort`, `format` = JSON schema as `jsontypes.Normalized`, wrapped by the provider into `{type: json_schema, schema}`), a top-level `cache_control{ttl}` and one per `messages[*]` entry; all `RequiresReplace`. Computed outputs: `stop_sequence`, `stop_details{category, explanation}` (null unless `message.JSON.StopDetails.Valid()`), `thinking_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `usage_service_tier`, `usage_inference_geo`. Plan→params and response→state live in `buildMessageParams`/`mapMessageToState` (unit-tested in `message_resource_internal_test.go`). Load-bearing details: the resource has its own `MessageResourceParamModel` because `MessageParamModel` is shared with `anthropic_count_tokens` (adding `cache_control` to the shared struct broke the data source at runtime); a zero-valued `anthropic.CacheControlEphemeralParam{}` is dropped by the SDK's `omitzero`, so `Type: "ephemeral"` is set explicitly; a top-level and a block-level `cache_control` must carry the same `ttl`. Verified live 2026-10-08 on `POST /v1/messages`: `thinking.type = "disabled"` is rejected (400) by `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5` (the sibling count_tokens endpoint behaves differently, see below); `adaptive` and `inference_geo` are rejected (400) by `claude-haiku-4-5-20251001`, so the acceptance tests use `enabled` + `budget_tokens = 1024`. Not in SDK v1.67.0, deferred until the #192 pin is lifted: `diagnostics.previous_message_id` and `thinking.type = "between_tools"`. `cache_control` on the `system` prompt alone is a breaking change tracked in [#312](https://github.com/ippontech/terraform-provider-anthropic/issues/312) (`system` becomes a list of content blocks in v2.0.0); the top-level `cache_control` covers it meanwhile

**Data sources:**
- `anthropic_count_tokens` (`internal/services/messages/count_tokens_data_source.go`) — counts tokens for a given prompt; accepts the same request-shaping inputs as `anthropic_message` (`thinking`, `output_config`, top-level `cache_control`, same shapes and validators, built by `buildCountTokensParams`). **No beta header**: the once-documented `thinking-token-count-2026-05-13` is unnecessary (verified live 2026-10-08, `thinking` without it returns 200). The endpoint is free and rate-limited independently from the Messages API. Model quirks measured live on 2026-10-08 on this endpoint: `thinking.type = "disabled"` returns 200 for `claude-fable-5-1` and `claude-opus-5-5` but 400 for `claude-sonnet-5-5` (the API asks for `between_tools`, absent from SDK v1.67.0), which differs from `POST /v1/messages` where all three reject it, so keep the two docs endpoint-specific; `output_config.effort` returns 400 on `claude-haiku-4-5-20251001`. `format = jsonencode(null)` decodes to a nil map and is rejected locally with the attribute-scoped `Invalid format` diagnostic rather than sent as `"schema": null`
