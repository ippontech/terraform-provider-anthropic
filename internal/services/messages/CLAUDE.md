# Messages service notes

Load-bearing details for `internal/services/messages/`: the `anthropic_message` resource and the `anthropic_count_tokens` data source (`client.Messages`, standard API key). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

**Resources:**
- `anthropic_message` (`internal/services/messages/message_resource.go`) — calls the Messages API; write-only, immutable (no read/update/delete). Inputs beyond `model`/`max_tokens`/`messages`/`system`/`temperature`: `stop_sequences`, `metadata.user_id`, `service_tier` (`auto`/`standard_only`), `inference_geo` (`us`/`global`), `speed` (`standard`/`fast`; the `fast-mode-2026-02-01` beta header that research-preview models require for any `speed` is not sent), `thinking` (`enabled` with `budget_tokens`, `disabled`, `adaptive`, `between_tools`, optional `display` only with `enabled`/`adaptive`), `output_config` (`effort`, `format` = JSON schema as `jsontypes.Normalized`, wrapped by the provider into `{type: json_schema, schema}`), a top-level `cache_control{ttl}` and one per `messages[*]` entry, `diagnostics{previous_message_id}` (cache diagnostics, GA: `{}` sends `"previous_message_id": null`, the documented first-turn opt-in, via `param.Null` because an empty `DiagnosticsParam` is dropped by `omitzero`); all `RequiresReplace`. Computed outputs: `stop_sequence`, `stop_details{category, explanation}` (null unless `message.JSON.StopDetails.Valid()`), `thinking_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `usage_service_tier`, `usage_inference_geo`, `usage_speed`, and `diagnostics.cache_miss_reason{type, cache_missed_input_tokens}` (Computed child of the Optional `diagnostics` block, `UseStateForUnknown`; null when the response's `diagnostics` or its `cache_miss_reason` is null, so "no divergence" and "comparison still pending" both read as null). Plan→params and response→state live in `buildMessageParams`/`mapMessageToState` (unit-tested in `message_resource_internal_test.go`; the exact request bodies and diagnostics are pinned in `message_params_internal_test.go`). `buildMessageParams` and `buildCountTokensParams` share `decodeMessages` (generic over the two message models through their `textBlock` methods), `thinkingParam`, `formatSchema` and `cacheControlParam`, but keep their own diagnostic wording and error flow: the resource accumulates its errors once the messages are read, the data source stops at the first. Load-bearing details: the resource has its own `MessageResourceParamModel` because `MessageParamModel` is shared with `anthropic_count_tokens` (adding `cache_control` to the shared struct broke the data source at runtime); a zero-valued `anthropic.CacheControlEphemeralParam{}` is dropped by the SDK's `omitzero`, so `Type: "ephemeral"` is set explicitly; a top-level and a block-level `cache_control` must carry the same `ttl`. Verified live 2026-10-08 on `POST /v1/messages`: `thinking.type = "disabled"` is rejected (400) by `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5` (the sibling count_tokens endpoint behaves differently, see below); `adaptive` and `inference_geo` are rejected (400) by `claude-haiku-4-5-20251001`, so the acceptance tests use `enabled` + `budget_tokens = 1024`. `between_tools` (SDK v1.76.0+) and `speed` (v1.82.0+) were not probed live; `between_tools` is what count_tokens asks for on `claude-sonnet-5-5` (below). `cache_control` on the `system` prompt alone is a breaking change tracked in [#312](https://github.com/ippontech/terraform-provider-anthropic/issues/312) (`system` becomes a list of content blocks in v2.0.0); the top-level `cache_control` covers it meanwhile. `output_config.format` must decode to a JSON object: `ModifyPlan` rejects any other JSON value, `jsonencode(null)` included, through `decodeFormatSchema` when it plans a create (a replacement is planned as a create with a null prior state), and `buildMessageParams` checks again a value that was unknown at plan. Not in the config validator: it runs on every plan, and a message created while a null format was dropped from the request must keep planning. `temperature` is deprecated ([#284](https://github.com/ippontech/terraform-provider-anthropic/issues/284): `DeprecationMessage`, template note, gone from the public example): API version `2026-10-21` (SDK v2) rejects it at any value, `1.0` included, so it is removed in `major/2.0.0` with #192. There is deliberately no "only 1.0" validator: under `2023-06-01` only Claude 4.7 and later models reject other values. An unset value is never sent (`TestBuildMessageParams_Temperature`)

**Data sources:**
- `anthropic_count_tokens` (`internal/services/messages/count_tokens_data_source.go`) — counts tokens for a given prompt; accepts the same request-shaping inputs as `anthropic_message` (`speed`, `thinking` including `between_tools`, `output_config`, top-level `cache_control`, same shapes and validators, built by `buildCountTokensParams`; no `diagnostics`, which the endpoint does not take). **No beta header**: the once-documented `thinking-token-count-2026-05-13` is unnecessary (verified live 2026-10-08, `thinking` without it returns 200). The endpoint is free and rate-limited independently from the Messages API. Model quirks measured live on 2026-10-08 on this endpoint: `thinking.type = "disabled"` returns 200 for `claude-fable-5-1` and `claude-opus-5-5` but 400 for `claude-sonnet-5-5` (the API asks for `between_tools`), which differs from `POST /v1/messages` where all three reject it, so keep the two docs endpoint-specific; `output_config.effort` returns 400 on `claude-haiku-4-5-20251001`. `format = jsonencode(null)` decodes to a nil map and is rejected locally with the attribute-scoped `Invalid format` diagnostic rather than sent as `"schema": null`
