# `internal/services/externalkeys/` service notes

Load-bearing details for `internal/services/externalkeys/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_external_key` (`internal/services/externalkeys/external_key_resource.go`) — registers a CMEK key record (Admin API, raw `admin.Client`, GA paths `/v1/organizations/external_keys[/{id}]` without `?beta=true`); `provider_config` is one Required single-nested attribute whose `type` (`aws`/`gcp`/`azure`) selects the fields (`providerConfigValidator`, an object validator, enforces required/forbidden fields per type); the deprecated `role_arn` is ignored by the API and not exposed; `region` (aws) is Optional+Computed with `regionFollowsKMSARN` (null for non-aws, prior value while `type`/`kms_arn` are unchanged, unknown otherwise so the API-derived region lands). `geo`/`provider_config` are editable in place while `attachment` is `unattached` and frozen once `attached` (archived workspaces count); `ModifyPlan` turns that into a **plan-time error** rather than `RequiresReplace`, because a replacement must delete the old key and the API refuses to delete an attached key, so it could only fail mid-apply (after creating an orphan key under `create_before_destroy`); a destroy plan of an attached key gets a warning, and `Delete` re-reads the key after a refusal to explain it (`removed` block / `state rm` hint). Update sends only the fields changed since state (`display_name` cleared with an explicit `null`, a removed azure `client_id` too, but only while the key stays azure: a switch to aws/gcp sends no `client_id`); an update left with nothing to send (a value unknown at plan that resolves to the stored one) reads the key with a GET instead of POSTing `{}`. An attached key whose frozen value is unknown at plan gets a warning (`unknownFrozenAttributes`): the guard cannot compare it, and a differing value fails at apply. Create/Read/Update keep the configured or stored `vault_uri` when the API returns it up to a trailing slash or letter case (`keepPriorVaultURI`; normalization unverified live). The optional provider_config strings reject `""` (`LengthAtLeast(1)`), which would come back null. An ARN-form `id` (Claude Platform on AWS) is planned unknown when `kms_arn` changes (`idFollowsKMSARN`: whether the API keeps the old ARN as the ID is undocumented). A removed `display_name` is sent as `null`; if the API keeps the name, Update reports it (`checkDisplayNameCleared`) rather than an inconsistent result (null-clearing unverified live). `attachment` has no `UseStateForUnknown` (a workspace can attach the key between applies). The ID is `url.PathEscape`d: on Claude Platform on AWS it is the KMS key ARN, whose `key/<uuid>` would otherwise add a path segment. No live test (#58, CMEK needs a real KMS key): httptest unit tests + `command = plan` native test

**Data sources:**
- `anthropic_external_key` (`internal/services/externalkeys/external_key_data_source.go`) — fetches a CMEK key record by ID (`ekey_...` or KMS ARN); shares `ExternalKeyModel`/`mapExternalKeyToModel` with the resource; 404 surfaces as `External Key Not Found`
- `anthropic_external_keys` (`internal/services/externalkeys/external_keys_data_source.go`) — lists CMEK key records; pages with `limit=100` + the opaque `page` cursor from `next_page` (not the `after_id`/`has_more` pair of the older organization lists), stops on a null or repeated cursor. Native tests for both use `mock_provider`; the acceptance smoke test is gated on `ANTHROPIC_CMEK_ACC=1` on top of `PreCheckAdmin`, since the terraform-tests organization was never checked for CMEK
