# `internal/services/rbac/` service notes

Load-bearing details for `internal/services/rbac/`. The root `CLAUDE.md` still applies; record new details about this service here, not in the root file.

**Resources:**
- `anthropic_rbac_group` (`internal/services/rbac/rbac_group_resource.go`) — manages a Claude Enterprise RBAC group (raw `admin.Client`, scoped Enterprise Admin API key created for all linked organizations, `read:`/`write:rbac_groups`); create and update (`POST …/rbac_groups[/{id}]`) accept only `name`; `role_ids` is **Computed only** (roles are attached in the claude.ai admin settings) and a Set, null when the API sends `null` (role data temporarily unavailable); under `anthropic-version: 2023-06-01` the API returns both `role_ids` and the deprecated `roles` (gone in 2026-10-21), so `mapRBACGroup` reads `role_ids` and falls back to `roles` only when `role_ids` is absent (`json.RawMessage` tells absent from `null`); `ModifyPlan` **warns** (not errors) on renaming or destroying a `scim` group, since the API's 400 depends on SCIM provisioning being on; every RBAC request carries `?beta=true`, as the SDK does; Delete tolerates 404
- `anthropic_rbac_group_member` (`internal/services/rbac/rbac_group_member_resource.go`) — adds a user to an RBAC group; composite ID `<rbac_group_id>:<user_id>`, both `RequiresReplace`, hard delete (404 tolerated); no single-member GET, so `Read` pages `GET …/{id}/members` (`page`/`next_page` cursor, stops at the page holding the user) and drops the resource when the user or the group (404) is gone; read-after-write consistency of that list was not probed
