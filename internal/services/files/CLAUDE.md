# Files service notes

Load-bearing details for `internal/services/files/`: the `anthropic_file` resource and the `anthropic_file` / `anthropic_files` data sources (Files API GA, `client.Files`, standard API key). The root `CLAUDE.md` still applies; where a note here says "see above" or "see below" and the target is not in this file, it is a section of the root `CLAUDE.md`. Record new details about this service here, not in the root file.

Known inaccuracy below, kept until the retry fix lands: multipart bodies are SDK-retryable in SDK v1.67.0, which buffers the body and replays it (see "Multipart uploads" in the root `CLAUDE.md`).

**Resources:**
- `anthropic_file` (`internal/services/files/file_resource.go`) — uploads and manages a file (Files API, **GA** — uses `client.Files`, not `client.Beta.Files`; the pinned SDK v1.67.0 ships both, and the GA service is required to get `expires_in_seconds`/`expires_at` and GA pagination/filters, see the files-API note below); standard API key; no Update endpoint (files can't be modified or renamed after upload) — `source_path`, `source_hash`, `filename`, `mime_type`, `expires_in_seconds` are all `RequiresReplace`; file content is never stored in state, only `source_path`, a `source_hash` SHA256 recomputed on every plan via a custom plan modifier (so an out-of-band edit to the file at the same path is detected and forces replace), and API metadata; local size (500 MB) and filename-charset validation happen before the API call; `POST /v1/files` is not idempotent, so its local retry helper (`uploadFileWithRetry`, used because multipart bodies aren't SDK-retryable) follows the `internal/admin` POST convention and retries **only on 429**, never on 5xx

**Data sources:**
- `anthropic_file` (`internal/services/files/file_data_source.go`) — fetches a single file's metadata by ID (`GET /v1/files/{id}`, GA `client.Files.GetMetadata`); standard API key; shares `mapFileMetadataToModel` with the plural data source (the resource keeps its own mapping); 404 surfaces as a `File Not Found` diagnostic
- `anthropic_files` (`internal/services/files/files_data_source.go`) — lists files (`GET /v1/files`, GA `client.Files.ListAutoPaging`, `pagination.PageCursor` driven by `next_page`/`?page=`, `limit=1000` per page; `before_id`/`after_id` return 400 on GA requests and are not exposed); optional `ids` filter (1–100 unique IDs, sent as `ids[]=` and **without** `limit`/`page`, which the API treats as mutually exclusive; unknown or deleted IDs are silently omitted); an empty result is an empty list, never null
