# Implementation issue template

Read at step 3 of `SKILL.md`, before writing the issues. Fill one copy per resource or data source. The paths follow the root `CLAUDE.md` (*Adding a resource or data source*, *Testing*); when the two disagree, `CLAUDE.md` wins and this template needs fixing.

For a data source, replace `_resource` with `_data_source`, `Resources()` with `DataSources()`, `examples/resources/<name>/resource.tf` with `examples/data-sources/<name>/data_source.tf`, and `resources/` with `data-sources/` in the template and docs paths.

````markdown
<One-line summary of what this implements.>

## Branch
`<branch-name>` (GitHub variant only; the PR opens once the first commit is pushed)

## API
- `METHOD /v1/<path>`: description

## SDK methods (anthropic-sdk-go, version pinned in go.mod)
- `client.Beta.<Service>.<Method>(ctx, params)` returns `ResponseType`

## Terraform schema
| Attribute | Type | R/W |
|---|---|---|
| `id` | string | Computed |
| `...` | ... | ... |

## Files to create / modify
- `internal/services/<service>/<name>_resource.go`: `package <service>`
- `internal/services/<service>/<name>_resource_test.go`: Go acceptance tests, `package <service>_test`
- `internal/services/<service>/<name>_resource_internal_test.go`: unit tests against an `httptest` server, `package <service>`, only when they need unexported symbols
- `internal/provider/provider.go`: register the factory in `Resources()`
- `examples/resources/<name>/resource.tf`: resource blocks and outputs only (embedded in the Registry docs)
- `examples/resources/<name>/versions.tf`: the `terraform {}` block
- `templates/resources/<name>.md.tmpl`: non-empty `subcategory: "<Category>"`
- `tests/<name>.tftest.hcl`: Terraform native test
- `docs/resources/<name>.md`: generated by `make generate`, never edited by hand

## Go acceptance tests
- `TestAcc<Name>Resource_basic`: create with a minimal config, check `id` is set, then an `ImportState` step
- a `CheckDestroy` function that verifies the object is gone (or archived) after destroy
- gated on `acctest.PreCheck`, `acctest.PreCheckAdmin` or `acctest.PreCheckOAuth`, matching the credential

## Terraform native test (`tests/<name>.tftest.hcl`)
```hcl
test {
  parallel = true
}

run "<name>_resource_creates_<name>" {
  module {
    source = "../examples/resources/<name>"
  }

  assert {
    condition     = output.<name>_id != ""
    error_message = "Expected <name>_id to be non-empty."
  }
}
```
Admin API and OAuth resources plan only (`command = plan`, dummy credential in a `provider "anthropic"` block of the test file); self-contained list data sources use `mock_provider "anthropic" {}`. Details in `CLAUDE.md`, *Terraform native tests*.

## Implementation
Conventions: the root `CLAUDE.md`, `internal/services/<service>/CLAUDE.md` when it exists, and the `terraform-provider` skill. Done when `make`, `make terraform-test` (or a stated reason it could not run) and `pre-commit run -a` pass.
````

Remove the lines and sections that do not apply rather than leaving them empty, because the implementing agent treats every listed file as work to do.
